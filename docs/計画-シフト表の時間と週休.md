# 計画：シフト表の「週の時間・週休」とシミュレーション（2026-10-22 ユーザーと一問一答・下書き）

## きっかけ
- 2027年4月から、こども部門の正社員を週休1日から週休2日に変えられるかを検討している（マネージャーの会議）。
  これまでは Excel（NAS の「2026年シフト検討用」・シート「2027案」）に名前を並べ、社員休みの列に休みの人を書いて、目で数えていた。
- 知りたいこと：人ごとの週の時間・週休、レッスン時間とその他業務の時間、目標まであと何時間か、人が足りない所、何人要るか。
- 週の時間は人によって違う（基本40時間・35・37.5・30 も）。週休も人によって違う（リーダー・マネージャーは週休1のまま、選手の方は週休1、など）。

## 決まったこと（ユーザー確定）
1. **アプリの「作業中の案」でやる**（案A）。決まった案を［決定］すれば、今までどおりシフト表になる（Excel に書き写さない）。
2. **いまの決定済みの表にも付ける**：人ごとに見るの右に「週のまとめ」。
3. **1日の勤務時間はシフト表の担当から組み立てる**（勤務表は使わない）
   - 出勤＝その日の最初の担当の30分前／退勤＝最後の担当の15分後（30・15 は表の設定で変えられる）
   - 人・曜日ごとに「9:30から」のように時刻でも決められる
   - 休憩は今の決まり（lib/breakCalc）で引く
4. **週のまとめ**：出勤日数・週休／レッスン時間（こども＋他部門＝大人・勉強会）／その他業務（勤務時間のうちレッスン以外）／**合計**／**目標**／**残り**（「あと 8:15」「3:30 超えている」）
5. **目標の時間**：こども部門の**正社員だけ**、既定40時間。人ごとに変えられる。パートは目標なし（合計だけ）
6. **見られる人**：シフト表を作る権限のある人と管理者だけ
7. **作業中の案の中だけでできること**（本番の勤務表・プロフィール・給与には触らない）
   - 人ごとの窓：週休（1・2・3）・目標の時間（40・37.5・35・30・ほか）・1日の時間（既定＝目標÷出勤日数・直せる）・**固定の印**（理由つき）
   - **まとめて変える**：変えるもの（週休か目標の時間か）・対象の役職（いくつでも）・「すでに◯の人は変えない」・固定の印の人は変えない。押す前に「変わる人◯人／変えない人と理由」
   - 変えたときの残し方：**見るだけ**（保存しない）／**新しい案として残す**（名前をつける）／**この案を上書き**
   - **仮の人**（新しい人A など）を置ける。仮の人が残っている案は［決定］できない
   - 曜日ごとの「足りない人数」
8. **新しい案の最初の値**：いまの週休＝勤務表（いつものシフト）の出勤曜日から数える（こどもの表に担当が無くてもフロントなどで出ている日があるため）。目標は40時間
9. **案を比べる**（今の「違うマスに印」を広げる）：①と②の数字（週休2の人・足りない人数の最も多い日・目標を超える人）と、人ごとの違い（週休・目標・残り・担当の違い）

## 作る順番（案）
- 段1：週のまとめ（決定済みの表と案の両方）・前後の時間の設定・人と曜日ごとの出勤時刻・目標（既定40・人ごと）
- 段2：案の中の人ごとの窓・まとめて変える・残し方の3つ・仮の人・曜日ごとの足りない人数・案を比べるの広げ
- 段3：その他業務の入力（人×曜日×時間「フロント 13:00〜16:00」「事務」など）と「あとどこに入れるとよいか」の候補
  （曜日ごとに、人が足りないマスと、その曜日に残りがある人を並べる）

## 作り（下書き・レビュー前）
- 計算は lib に1か所（supabase を読まない側・画面を開かずに検算できるように）。決定済みの表・案・比べる・印刷が同じものを呼ぶ
- 前後の時間（30・15）：kids_shift_settings に列（こども・大人で共通か別か＝要相談）
- 人・曜日ごとの出勤時刻、目標の時間（決定済みの表のぶん）：新しい表（GRANT を同じ migration に）
- 案のぶん（人ごとの週休・目標・1日の時間・固定の印と理由・仮の人）：案に紐づく新しい表。案を［決定］したときに本番へ写すかは要相談
  （週休・目標は勤務表・人の設定。決定で勤務表を書き換えるのは影響が大きいので、写さない案が今のところ有力）
- 見られる人の判定は今のシフト管理と同じ（DB の権限も同じ）

## レビュー（2026-10-22・シニアエンジニアと UI/UX の2体・主な指摘は自分でコードを見て裏取りした）
- 🚨 担当の時刻が無い出勤日（フロント・事務・校の役割だけ・園指導・勤務表だけの日）は 0時間になり、正社員ほど「残り」が大きく出る → 扱いを決める（下の Q1）
- 🚨 合計の元が2つある（担当から組み立てた時間／目標÷出勤日数の「1日の時間」）→ 合計は担当から組み立てた時間。「1日の目安」は1日の長さのチェックだけに使う（おすすめ）
- 🚨 時刻の取り方が場所ごとに違う：人ごとの表は始まりの時刻だけ・終わりの無い行の長さの既定（こども50・大人30）が3か所・共通の人の「何時まで」が空＝24:00（lib/shiftCross）。
  計算は lib に1本（crossEntriesOf を土台に）・重なった時間は1回だけ数える・24:00 を超えない
- 🚨 休憩：朝の園指導〜夜のクラスを1つの時間にすると空き時間まで勤務に入る。空きが◯分以上なら時間帯を2つに分けて、それぞれに calcSegmentBreak（会社の決まり・13:00 で表が変わる）
- 🚨 仮の人をマスに置くには kids_shift_item_people.user_id（profiles への必須の参照・確認済み）・check_items・マスの署名3か所・決定の関数を作り直すことになる＝シフト表でいちばん危ない所。
  はじめは「マスに置かず、曜日ごとの足りない人数に足す」形で足りるか（下の Q4）
- 案の前提の表（kids_shift_plan_people など）は security definer の関数で書き、revision を上げる（ほかの人の画面に「変わりました」が出る）。案の写し（copy_from）で前提も写す。仮の人が残る案の［決定］は DB でも止める
- 案の中の社員休み・⚠️ は今は勤務表から決めている → 週休を変えた案では食い違う。案では前提とマスから決める
- 追加必要の数え方が画面の中に分かれている → 先に lib へ移してから、週のまとめ・比べるを作る
- レッスンに数える行の種類は kids_shift_row_kinds に印の列（コードに直書きしない）。役割（勤務中・サポート・見守り・補助）を数えるか決める（下の Q3）
- 勉強会は参加者から直接数える（今の出し方は列の無い校の勉強会を落とす）。掃除は時刻と長さがあるので数えられる
- 前後の時間（30・15）は kids_shift_settings の列（1行だけの表＝こども・大人で共通）
- 目標・出勤時刻（決定済みの表のぶん）は有効期間つきで持つ。目標は人ごとに1つ（こども・大人で分けない）
- 新しい表は GRANT を同じ migration に・読み書きは can_manage_admin_tab('shift_patterns')・関数は anon を revoke して実測
- まとめて変えるの役職は role_id で選ぶ（役職名で判定しない）
- 画面：週のまとめは人ごとに見るの中の［週のまとめ］で、名前とまとめだけの表に切り替える（スマホに入る）。列は 名前｜目標まで｜合計／目標｜レッスン｜レッスン以外｜出勤（週休）
- 画面：表の上に何を数えているかを1行（「シフト表の担当から計算しています（担当の30分前〜15分後）…」）。自動の値は灰色で「（自動）」、手で決めた値は［自動に戻す］
- 言葉：残り→「目標まで（あと 8:15／8:15 超え）」・その他業務→「レッスン以外」・目標→「週の目標時間」・固定の印→「まとめて変えない」・1日の時間→「1日の目安」
- 「目標を超える」と「週40時間を超える」は分けて数える
- 「見るだけ」は、閉じる・移る・案を切り替えると気づかず消える。今の案には「下書き→［案を保存］」があるので保存の仕方が2つになる（下の Q2）
- ［決定］しても週休・目標は勤務表に写らないことを、決定の確認に書く
- 段を小さく：1a（DB の変更なし・決定済みの表の週のまとめ・30/15/40 は決め打ち）→ 1b（設定の列・人ごとの目標と出勤時刻）→ 2a（前提の表・人ごとの窓・残し方）→ 2b（まとめて変える）→ 2c（比べる）→ 2d（仮の人）→ 段3

## 作ったもの（2026-10-22・ユーザー「いっきにやって」）
- ユーザー確定（レビューのあと）：勤務時間は 決定済みの表＝勤務表／案＝担当の前後から（Q1 案A）。シフト表に無い時間は「事務」として入れる（フロントなどに分けない）。
  仮の人は人数だけでなくマスに置く（「仮1」→入社したら「この人を仮1に」）。休憩は空きで時間帯を分けて当てる。言葉は「目標まで」「レッスン以外」
- こちらで決めた既定（あとで変えられる）：分ける空き 60分（設定）／レッスン以外に数える行の種類＝大人コース業務・共通の人・事務・打合せ・その他（行の種類の「レッスンに数える」）／
  （ ）出勤・レッスンに入らない人はレッスン以外／勉強会はレッスン以外／見るだけ＝まとめて変える窓の中の一覧（閉じれば何も変わらない）・残し方は［この案に入れる］［新しい案として残す］／
  仮の人の名前は「仮1」「仮2」…（表ごと）／足りない人数＝シフト表の「追加必要」の曜日ごとの合計／あとどこに入れるとよいか＝足りないマスと、その時間が空いていて目標まで残っている方（3人まで・休みの日は「休みの日」と添える）
- DB（migration 20261022090525・本番に適用・実測）：kids_shift_settings に pre_minutes・post_minutes・gap_split_minutes／kids_shift_row_kinds.counts_as_lesson／
  表 kids_shift_person_targets（決定済みの表の目標）・kids_shift_temps（仮の人）・kids_shift_plan_people・kids_shift_plan_person_days（案の前提・書くのは kids_shift_plan_save だけ）／
  kids_shift_item_people.temp_id（user_id か temp_id のどちらか）＋トリガー kids_shift_item_people_temp_guard（仮の人は案のマスだけ）／
  関数を本番の実定義から作り直し：cell_sig・payload_sig（仮の人は 'temp:<id>'・今ある署名は変えない）・check_items・put_items・copy_items・plan_save（op 'terms'・'assign_temp'・写すときに前提も写す）・plan_decide（仮の人が残っていれば reason 'temps'）
- 画面：lib/shiftWeekSummary（計算1か所・画面を開かずに検算24項目）／components/admin/ShiftWeekView・ShiftPersonTermsDialog・ShiftBulkTermsDialog／KidsShiftPanel の［週のまとめ］・マスの「人を選ぶ」に仮の人（案だけ）・
  設定（30・15・60）・行の種類の「レッスンに数える」／lib/kidsShift（仮の人は画面で user_id='temp:<id>'）・lib/kidsShiftApi（送るときに temp_id）
- 社内FAQ 2件（migration 20261022093449・分類「シフト管理」・マネージャー以上）
- 🚨 決まりごと：仮の人は決定済みの表に入らない（DB のトリガーで止める）。仮の人を消せるのは、どの案のマスにも入っていないときだけ（restrict）。
  前提を保存すると案の revision が上がる（ほかの人の画面に「別の人がこの案を保存しました」が出ることがある）。案を［決定］しても、週休・目標は勤務表に写らない
- 🚨 わかっている限界：案の中の ⚠️・社員休みは今までどおり勤務表から（週休を変えた案では ⚠️ が増えることがある）。決定済みの表で、担当が勤務表の時間の外にあると、レッスンが勤務より長く見えることがある

   | その日の状態 | 送るとどうなる |
   |---|---|
   | 何も無い・過ぎた日 | 事後報告 |
   | 何も無い・先の日 | 事前申請 |
   | 何も無い・今日 | 勤務の開始前なら事前申請／開始後なら事後報告（行に表示） |
   | 事前申請（確認待ち・受理済み）・報告できる時刻を過ぎた | 実績報告。実績欄に予定が最初から入る。そのまま＝予定どおり／直した＝変更あり（変わった理由が必須） |

## 4. 画面
- 残業ページ「申請・報告」タブに ［📋 表でまとめて入力（試験中）］。権限と PC の両方を満たすときだけ出す
- 単位は**給与期間1つ（16日〜翌15日）**。◀▶で移る。ページの最大幅（今は600px）は表のときだけ広げる
- 列：日付／通常シフト（行ごとに手直しできる）／この日の状態／実際の時間（2本目は［＋］）／休憩（自動・手直し可・「手入力」の印と［自動に戻す］）／
  労働・差分／種別（自動判定。開始が遅い・終了が早いときだけ「調整／遅刻・早退」の2択）／勤務地（既定はシフトの校）／理由（［上と同じ］）／送ると
- 日付の列と見出しは固定。横スクロールは表の中だけ
- キーボード：時刻は「930」と続けて打てる（TimeInput の既存の動き）。Enter で同じ列の下の行へ
- 行を触った時点で、その日の通常シフトを入れる（🚨 2本シフトの2本目の入れ忘れで大きなマイナスになるため）
- 下書き：端末に保存（`draftStorage` に1キー）。🚨 **キーに利用者IDを含める**（共用PCで前の人の時刻・理由が見えないように）。
  開き直したとき、既に申請がある日の下書きは捨てて一言知らせる

## 5. エラーと状態
- 行の状態は4段：**入力中**（灰・行を離れるまで赤くしない）／**変更なし**（灰・送らない。🚨 通常シフトと同じ日をエラーにしない）／
  **注意**（黄・送れる：休憩が法定より短い 等）／**エラー**（赤・送らない）
- 表の上に「送れる ◯件（内訳）／エラー ◯件／変更なし・空 ◯日」と［エラーの行だけ表示］
- 🚨 **通常シフト（weekly_shift_patterns）・会社カレンダー・既存の申請のどれかが読めなかったら、送信ボタンを止める**
  （今の1件フォームは型の読み込み失敗を見ておらず、表だと全行が休日出勤の誤った値になる）
- 締め：給与期間ごとに決まるので、行ごとではなく**表の上のバナー1つ**で止める（経理の許可がある日だけは送れる）
- 🚨 **送る直前に行ごとに検証をやり直す**（今の時刻に依存するチェックがあるため）

## 6. 送信
- ［◯件を確認して送信］→ 確認（申請先ごとにまとめて）→［送信する］。🚨 二度押しは ref で止め、押したらボタンを消す
- **1行ずつ順に**送る。途中で失敗しても他の行は止めない。行の状態が「送信中→送信済み／失敗（理由）」に変わる。「3/8件」
- 送信中は表の入力を止め、ページ離脱時はブラウザ標準の警告
- 🚨 **申請本体と時間帯は別々に保存している**（今の1件フォームも同じ）。時間帯だけ失敗したら **取り消さずに**、その phase を delete→insert で2回まで入れ直す。
  それでも失敗したら「要確認」＋［時間帯だけ入れ直す］（§10-1）
- 🚨 **23505（同じ日が既にある）**：その日を読み直し、**中身が一致したときだけ**「送信済み」。違えば「既に申請あり（要確認）」で通知も送らない（§10-4）
- 申請をすべて入れ終えてから、カレンダー同期（gcal-sync）を1件ずつ順に呼ぶ。失敗は「送信済み（カレンダー未反映）」の警告
- 通知：ベルは1件ずつ（今と同じ）。メール・Slack は申請先ごとにまとめて1通（自己受理の Slack confirmed もまとめる）。
  🚨 新しい通知の種類は作らない（event_key は今の `overtime:new_request` 等を使う＝設定の行が無い＝全員、の穴を開けない）
- 途中で閉じたとき：送れた分は送れている。通知を送る前に閉じた分は、次に開いたときに「通知が届いていない申請」を出して送り直せるようにする
- 送信後：薄緑カード「◯件を送信しました。エラーの◯件は表に残っています」

# 計画（案）：連絡板の「送信の取り消し」（Gmail と同じ）と、大きな作成の画面（2026-10-26）

## きっかけ（ユーザー）
- 2026-10-26 18:11、まちがえて送ったお知らせを管理者が消した。本文・ベル・送信の記録は消せたが、スマホの通知とメール（件名と送った人の名前）は届いたあとで取り消せなかった
- 「Gmail と同じように、送信後10秒ほど取り消せるとよい。取り消したら下書きに戻す」

## 決まったこと（ユーザー）
- 対象：お知らせ（一斉・個人あて）・グループ・DM の全部
- 秒数は出さない。［送信］のあと画面の下に「送信しました［取り消す］」が10秒出て消える
- 押さなければ、ほかの画面に移っても10秒後に送る。アプリを閉じた・通信が切れたときも送る（送られずに消えることはない）
- ［取り消す］を押したら、入力していた内容（件名・本文・宛先・設定）を作成の画面に戻す
- 安否確認・「⚡当日の連絡・緊急」は待たずにすぐ送る（取り消しは付けない）
- 「件名・期限・種別・送信予約」を開いたら、大きな作成の画面に切り替える（中のスクロールは1つ・［送信］はいつも下に見える・本文は書いた分だけ伸びる・閉じると今の小さな入力欄）

## 今の作り（client/src/pages/BoardPage.tsx）
- ふつうに送る：画面が board_messages に insert → 続けて画面が notifications に insert（ベル → push_queue のトリガー → push-dispatch でスマホ）・メールも画面から（send-email）。
  お知らせ（2469 行あたり〜2507）・グループの投稿（1897〜2043）・スレッドの返信（2027）・DM の一斉（2248〜2259）
- 送信予約：status='scheduled'・scheduled_at → cron（5分ごと・10/26 から「予約の時刻が過ぎた予約があるときだけ」呼ぶ）→ Edge Function board-scheduled-send が status を sent にしてベル・メール（宛先は board_message_recipients。🚨 グループ・DM の予約がどう送られるかは要確認）
- 受け取る側の一覧は status='sent' だけを出す（要確認）

## 案
### 作り（2案・どちらがよいか見てほしい）
- 案X（予約の仕組みを使う）：［送信］で status='scheduled'・scheduled_at=今＋10秒で insert。10秒たったら画面が「今すぐ送って」を呼ぶ（board-scheduled-send を呼ぶか、自分のメッセージだけを送る RPC）。画面を閉じていたら cron が拾う（最大5分おくれ）。
  ［取り消す］＝ status='scheduled' の行を消す（または draft に戻す）→ 画面に内容を戻す
  - よい：アプリを閉じても必ず送られる・相手には10秒の間なにも見えない
  - 気になる：ふつうに送るときのベルの文・スマホの通知の題名（グループ名）・急ぎの印・メールの文が、予約の送り方（board-scheduled-send）と同じでないと、送り方で中身が変わる。グループ・DM・スレッドの返信の予約の送り方がまだ無いかもしれない
- 案Y（画面で10秒待つ）：［送信］で今の送る処理を10秒あとに動かす（ページを移っても動くよう、画面全体で1つの係に持たせる）。［取り消す］＝ 待っている処理をやめる
  - よい：送り方は今のまま（中身が変わらない）
  - 気になる：10秒の間にアプリを閉じる・スマホが眠ると送られない（ユーザーの「必ず送る」に合わない）。端末に「送る途中」を控えて、次に開いたときに送る手当てが要る

- 取り消したら緑の帯「送信を取り消しました。内容は作成の画面に戻しています。」

## 見てほしいこと
- 案X と案Y のどちらが安全か（二重送信・送られない・中身が変わる・取り消したのに届く の起きにくさ）
- 10秒の間に、相手の画面・ベル・スマホ・メール・既読・未読の数・送信トレイにどう見えるか
- 取り消しと送信が同時に起きたとき（ちょうど10秒目）
- 予約の仕組み（board-scheduled-send・cron）を使うときに直す所
- 大きな作成の画面で気をつけること（スマホ・パソコンの低いウィンドウ・下書き draftStorage）

## レビュー（UI/UX・シニアエンジニアの2体・2026-10-26）で決め直したこと（大事な所は本番とコードで裏取り済み）
### 作り：案X を直した形（案X改）
- 案Y（画面で10秒待つ）は、閉じた・眠った・2つのタブで「送られない／遅れて送る／2回送る」を防げないので採らない
- board_messages に send_hold（取り消し待ちの印）・push_urgent（急ぎの印）・send_batch（DM の一斉をまとめて扱う）。status='scheduled'・scheduled_at はサーバーの時計で今＋10秒
- 関数を4つ：①作る（本体・宛先・写しを1つの取引で・番号は端末で作る＝押し直しても2件にならない）②届ける（送信済みにするのと同じ取引で宛先を決めてベルを入れる・service だけ）③今すぐ送る（10秒たったら画面が呼ぶ）④取り消す（本人・印あり・まだ送っていない行だけ消す。消せた件数で画面が決める）
- 「宛先を決めてベルを作る」をふつうの送信・予約・急ぎ・取り消しのあとですべて②に1つ。Edge（board-scheduled-send）はメールだけ（まとめて送る）
- 閉じたときの予備は毎分のジョブに相乗り（送るものがあるときだけ Edge を呼ぶ・5分ごとのジョブは消す）→ 遅れは最大1分ほど
- 取り消しの係は画面全体に1つ（ページを移っても10秒の時計と送信が続く）
### 🐛 いま起きている穴（一緒に直す・本番とコードで確認）
- グループ・DM の送信予約が、送った瞬間にベル・スマホ・メールを出している（予約の時刻より前に届く）
- 予約で送るお知らせは、送った本人にもベルとメールが届く（Edge が宛先全員に送る）・宛先0件でも黙って送信済みになる・送信済みにしてからベルを作るので途中で落ちると届かない・メールの .invalid を除いていない
- ナビの数（my_board_unread）のグループ・返信の数え方と、読む権限・検索が status を見ていない＝予約中の投稿が数に入る・API から読める
- スレッドに返信するたび、グループ全員にメールが行く（わざとか要確認）
### 画面
- 帯は「入力欄のすぐ上」（グループ・DM・スレッド）。お知らせは送信トレイへ移るので画面の下。新しい版の帯・自動ログアウトの帯と重ならないように積む
- 色は会社の決まりの薄緑（成功のカードと同じ）・［取り消す］は白に灰色の枠・押しやすい大きさ（44px 以上）・出てから0.5秒は反応しない（［送信する］を押した指のぶれで取り消さない）
- 帯が消えたあとも、まだ送っていない間は送信トレイ／自分の吹き出しに「送信待ち・まだ相手には届いていません［取り消す］」
- 取り消したら、送る直前の入力をすべて戻す（宛先・件名・本文・種別・期限・返信を受け付ける・写し・急ぎ）。今の下書きは一部しか持たないので、別に覚えておく。書きかけがあれば「置き換えますか」
- 間に合わなかったとき（ちょうど10秒目）：「すでに送信されたため、取り消せませんでした。送信トレイから削除できますが、スマホの通知とメールは取り消せません。」
- 圏外で取り消せないとき：「通信がつながらないため取り消せません。このまま送信されます。」（内容は戻さない＝2件届くのを防ぐ）
- 大きな作成の画面は、今ある［⤢］（全画面）と1つにまとめる・上に「送信先：◯◯」・右上は［小さくする］・小さく戻したら「件名あり・期限 11/2・予約 11/1 9:00」の小さな札
- 急ぎ・安否確認は取り消しなし（送る前の確認に「（取り消しはできません）」）・自分で送信予約したときは「11月1日 9:00 に送信します（予約済みから取り消せます）」

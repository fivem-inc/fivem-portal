## ✅ 決まったこと（ユーザー確定）
- 対象：残業申請の **勤務地変更・遅出・早退**（2026-10-20）。
  「遅出・早退」は4つとも（遅刻 tardiness・早退 early_leave・調整遅出 late_start_adj・調整早退 early_end_adj・lib/overtimeTypes）。
  🚨 選べるのは**事前申請のときだけ**（2026-10-20 ユーザー確定「すべているのでは　事前なら」）
- 選ぶのは受理のとき（2026-10-20・社長の案）：
  - 本人がマネージャーで自己受理 → 送る前の確認で選ぶ
  - ほかの人の申請 → マネージャーが**事前申請を受理するとき**に受理の画面で選ぶ（経理が代わりに受理するときも）
  - 実績報告・事後報告（終わった日）・出張報告から作った申請では出さない
- 言い方は今の休みのときにそろえる（2026-10-20 ユーザー確定 案A）：
  見出し「シフト調整（四条本校 13:00〜15:00 いない時間）」／ボタン［必要］［調整不要］。
  初めは［調整不要］（休みのときは［必要］が初め）→ 説明の1行「代わりが必要なときだけ『必要』を選んでください。」で補う
- いない時間：遅出＝いつものシフトの始まり〜実際の始まり／早退＝実際の終わり〜いつものシフトの終わり／勤務地変更＝いつものシフトの時間（移動の時刻は記録に無い）
- 相談の見出し：「◯◯さんの遅出」「◯◯さんの勤務地変更（上桂校へ応援）」＋「いつもの校」「代わりが要る時間」

## 1回目のレビューで分かった注意（勤務地変更だけの案のとき・UI/UX とシニアエンジニア）
- 受理が2回（事前申請の受理→実績報告→確認）。今の shift_adjust_recompute は実績報告済み（reported）を見ないので、そのまま足すと実績報告で相談が「取り消されました」になる→判定は「一度受理された・取り消されていない」に
- shift_adjust_not_needed は既定 false＝必要。使い回すと既定の向きが逆になる→新しい列（例 shift_adjust_needed・既定 false）
- 勤務地変更は自動で付く種別（いつもの校と違う・移動あり）。いつもの移動（A→B）の人はいつもどおりでも付く→「申請の校 ≠ いつもの校」のときだけ出す
- 相談を見る人は残業申請の表を読めないことがある→相談の行に校・時間を写す
- 今ある抜け：勤怠カレンダーの「シフト未調整だけ」が残業申請の行を出さない／シフト調整のタブの見出しに残業申請の終日の休みの校が出ない

## 2回目のレビュー（遅出・早退を含めた案・2026-10-20・UI/UX とシニアエンジニア）
- 言葉は終日とそろえる（案A）に2人とも賛成。「判断がつかない場合も必要を」の一文（SHIFT_ADJUST_SELF_NOTE）は遅出などでは出さない（初めの選択と食い違う）
- 救済ボタン［シフト調整を相談する］は要る（初めが［調整不要］だと、後から相談を作る道が無い）→ ✅ 置く（2026-10-20 ユーザー確定）。
  置き場所：受理済みの申請（上長の確認ページ・管理画面の残業の一覧）／押せる人：マネージャー以上（シフト調整の権限）／押せる期間：いない時間が始まる前まで
- DB：新しい列 overtime_reports.shift_adjust_needed（既定 false）。shift_adjust_not_needed は使い回さない。
  きっかけは 'ot_partial' を1つ足し、中身（種別・理由 late/early_situation・校）を相談の行に写す。
  いない時間は from/to の1組ではなく時間帯の並び（jsonb・shift_adjust_assignments.segments と同じ形）＝遅出と早退が同じ日・2本シフトに対応。
  計算は「いつものシフトの帯 − 予定の帯」の前後だけ。勤務地変更はシフト全体を初めの値にし、決める人が直せる（移動の時刻は記録に無い）
- 🚨 残業の時間帯は申請の行のあとに別の表（overtime_report_segments）へ入る（消す→入れ直す）→ 時間帯の表にもトリガー。0件のときは前の値を残す
- 実績では作り直さない（予定だけ見る）。決めたあとで時間・範囲が変わったら「⚠️ 決めたあとで時間が変わりました」（決定したときの値と比べる）
- 見る順は 休暇 → 終日 → 欠勤 → 部分（休暇は1日単位）。部分で決めたあとに休暇が受理されたら決め直しの印
- 判定は「必要 かつ 一度受理（request_confirmed_at） かつ 取り消されていない」。差し戻し後の出し直し中も相談は残る→見出しに申請の今の状態
- 見張りのトリガー：true にできるのは「自己受理の追加」か Edge Function だけ。事後報告・過ぎた日・出張から作った申請は不可。本人が後から立てられない
- overtime-approve は［必要］を黙って無視しない（条件外は 400）。送られてこなければ今の値のまま（古い画面でも壊れない）
- 修正依頼で出し直したときは、元の申請が［必要］なら受理の画面の初めも［必要］
- 代わりの候補：いない時間に空いているか・どの校かで分ける（前後に勤務している人＝延長できる人を上に）。入力欄にいない時間と校を最初から入れる
- まとめて申請・表入力は最初の版では出さない（救済ボタンで拾う）
- 文：「◯◯さんの遅出（四条本校 13:00〜15:00 不在）」「◯◯さんのこの日のシフト」「元の申請が取り消されました」。毎朝のまとめは「済んでいない相談」。1か月前のお知らせは対象外
- 量：SQL 300〜400行・Edge Function 40〜60行・画面 300〜450行（合計 700〜900行）。順番は DB（入れても運用は変わらない）→ Edge Function → 画面
- 出す前に直す：勤怠カレンダーの「シフト未調整だけ」が残業申請の行を出さない（毎朝のまとめ・1か月前のお知らせの着地点）
- 決めること：［必要］を選べる人（受理できる人なら誰でも／シフト調整の権限 leave_shift_adjust がある人）

# 計画：給与の締め日のお知らせ（毎月14日・自動）

2026-10-14 ユーザー確定（一問一答）。モック：配布資料/締め日のお知らせ_モック2.png（リポジトリ管理外）

## いまの運用と、変える理由
毎月、経理担当が前日に全員へメールで「明日15日は給与の締め日です。残業申請表の記載漏れ・上司チェック・交通費の提出を」と送っている。
10/16 から残業がアプリにまとまり、全スタッフが使うので、アプリから自動で、**その人に関係する行だけ**を届ける。

## 決まったこと
1. 送る日：毎月14日 10:00（JST）。14日が会社カレンダーの「会社休（closed_all）」なら、その前の会社休でない日の 10:00。土日は休館日扱いしない。
   文中は「明日」ではなく日付（「11月15日（日）は」）。
2. 届け方：ベル＋スマホ＋ホームのバナー。バナーは［✕］で閉じられ、15日の終わり（JST）で自動で消える。閉じたらその月はもう出ない。
3. 行ごとに届く相手を決める。権限は権限管理（feature_permissions）と雇用形態で決まる。新しい権限スイッチは作らない。

| 行 | 届く人 | 文（初期値・通知設定で直せる） |
|---|---|---|
| はじめ | 下のどれか1行でも届く人 | {締め日}は給与の締め日です |
| 残業 | 残業（overtime）ON | 残業申請の出し忘れや、実績報告がまだの日がないか、確認をお願いします。 |
| 受理まち | その時点で自分が受理する残業申請が残っている人 | 受理がまだの残業申請が{件数}件あります。15日までに受理をお願いします。 |
| 勤務変更 | 勤務変更報告（shift_report）ON かつ 雇用形態パート | シフトと違う勤務をした方は、勤務変更の報告もお願いします。 |
| 確認まち | その時点で自分が確認する勤務変更が残っている人 | 確認がまだの勤務変更が{件数}件あります。15日までに確認をお願いします。 |
| 交通費 | 交通費（expense）ON | 交通費の申請がまだの方は、15日までに申請をお願いします。 |
| 定期券 | 交通費 ON かつ 正社員（パート以外） | 定期券は、原則6か月定期で購入してください（入社6か月未満の方は3か月定期）。 |
| おわり | 届く全員 | ご不明な方は、経理担当までご相談ください。 |

   - 受理まち・確認まちは役職で決めない（実データ：残業の受理はマネージャーがほぼ全部、勤務変更の確認はリーダー・フロア責任者もしている）。
   - 件数の数え方はナビの数字と同じ（App.tsx）：
     残業＝overtime_reports の reviewer_id=本人・entry_type='manual'・status in ('requested','reported')（自分で受理する申請は除く？→レビューで確認）
     勤務変更＝shift_reports の reviewer_id=本人・status in ('pending','resubmitted')
   - 勤務変更報告がONでも正社員には勤務変更の行を出さない（上の役職のONは、パートの報告の確認・代わりに出すためのもの）。
   - 定期券の行は交通費の注意事項（ExpenseForm）と同じ内容。2か所に書く（ユーザー確定 案2）。通知設定の欄に「決まりが変わったら両方を直す」と書き添える。
4. 交通費の画面の注意事項「定期券は原則6か月定期…」の行は、正社員にだけ出す（パートには出さない）。
5. 文面・ON/OFF を直す場所：管理画面「通知設定」に「📅 締め日のお知らせ」の欄。行ごとの文面／ベル・スマホ・バナーの ON/OFF／
   「見え方」（役職・雇用形態・受理まちの有無を選んでプレビュー）／［自分に試しに送る］。経理担当のお名前はここで入れる（リポジトリに名前を置かない）。

## 作り（案）
### DB
- 設定：app_settings key='payroll_close_notice'（jsonb）：{ bell, push, banner, lines: { intro, overtime, ot_pending, shift, sr_pending, expense, commuter, outro } }。
  読み＝ログイン者（既存ポリシー）／書き＝管理者（既存ポリシー）。
- 送った記録：payroll_close_notices(close_date date PK, sent_at, sent_by_test bool…) と
  payroll_close_notice_recipients(close_date, user_id, notification_id, dismissed_at, PK(close_date,user_id))。
  本人は自分の行だけ読める・dismissed_at は RPC でだけ書く。
- 文面を組み立てる関数は1つ（SQL）：payroll_close_notice_compose(p_user uuid, p_close date) → jsonb [{key, text, count}]。
  cron の送信・バナー（本人の RPC）・プレビュー・試し送信のすべてがこれを呼ぶ（同じ判定を2か所に書かない）。
  プレビューは「役職・雇用形態・件数」を引数で受ける版（compose の中身を共通の内部関数に分ける）。
- 送信：payroll_close_notice_daily()（cron 毎日 01:00 UTC＝10:00 JST）。
  その月の送る日（14日から会社休をさかのぼる）以上・15日以下で、まだ送っていなければ送る（取りこぼしたら翌日に送る）。
  対象＝is_active の人で、compose の結果が「はじめ・おわり」以外に1行以上ある人。
  notifications に1行（message＝「11月15日（日）は給与の締め日です」・sub_message＝本文・source_type='payroll_close'・
  event_key='payroll:close_notice'（スマホ OFF のときは null＝プッシュに乗らない））。
  🚨 message に「お知らせ」「リマインド」を入れない（ベルの飛び先が連絡板になる）。
- バナー：my_payroll_close_notice() → 今が送信〜15日の終わりで、送った相手に入っていて、閉じていなければ compose の結果（件数はその時点）を返す。
  dismiss_payroll_close_notice(p_close date)。
- 掃除：毎月1日に 2年より古い記録を消す cron。
- 新しい関数は anon を revoke（has_function_privilege で実測）。

### Edge Function
- push-dispatch（共用）の EVENT_MAP に 'payroll:close_notice' を1行（url '/'・text は固定「15日は給与の締め日です」）。deploy 前に git fetch。
  → ロック画面に出るのは日付の入らない固定文（EVENT_MAP の text は固定のため）。

### 画面
- App.tsx（共用）：ホームに PayrollCloseBanner（新しい部品ファイル）を1行・classifyNotif に payroll_close の飛び先（ホーム）。
- ExpenseForm：useAuth の employmentType で注意事項の定期券の行を出し分け（番号は詰める）。
- NotificationsTab.tsx（共用）：カスタム欄の並び（PushBannerSettingsSection などの所）に新しい部品 PayrollCloseNoticeSection を1行。
- FAQ：締め日のお知らせ（届く内容は人によって違う）を1件足すか検討。

## 確かめること（作ったあと）
- 送る日の計算：14日が会社休・13日も会社休・14日が土日 などで begin/rollback。
- なりすましで パート／一般／マネージャー（受理まちあり）の compose の結果がモックと同じ。
- 二重に送らない（同じ日に2回呼ぶ）。取りこぼしの翌日送信。
- 社長端末にだけ試しに送る（宛先を絞る）。

## レビュー（UI/UX・シニアエンジニアの2体）を受けて決めたこと（2026-10-14・実装済み）
- 最初は「送る」OFF・最初に送る締め日 2026-11-15（取りこぼしの翌日送信で 10/15 に10月分を送らないため）。実機で試してから管理画面で ON
- 試し送信は「送った記録」に書かない（本番を止めない）。ベル1件だけ（本文はベルに入る・バナーは出ない）
- 受理まち・確認まち：勤務日が締め日まで・自分あて（reviewer_id = applicant_id）を除く。ナビの数字より少ないことがある
- 交通費の行は「交通費の申請がまだの方は、15日までに申請をお願いします。」（ユーザー確定 案1）
- 定期券の文は3か所同じ：「定期券は、原則6か月定期で購入してください（入社6か月未満の方は3か月定期）。」（ExpenseForm の注意事項・お知らせ・FAQ）。注意事項は正社員だけ
- 退職して申請できる期間中の人にも送る（退職者に許した機能だけ・受理まちなし）。「管理者」の共用アカウントには送らない
- スマホの文（固定）：「15日は給与の締め日です。申請の確認をお願いします」
- ベル：「◯月◯日（◯）は給与の締め日です／申請の確認をお願いします（くわしくはホームの案内をご覧ください）」。押すと /?payroll=1 で、閉じたバナーも開き直す
- バナーのボタン：［残業申請を開く］［勤務変更を開く］［↓ 交通費の申請へ］（ホームが交通費の画面）。受理・確認のボタンは下の既存バナーにあるので置かない。✕とボタンは44px
- ✕で閉じるとベルも既読。件数が0になった行はその場で消える（useRefreshOn と pending-changed）
- 雇用形態は本番でパート・正社員の2つだけ（2026-10-14 実測）。勤務変更の行＝パート、定期券の行＝パート以外
- 関数：payroll_close_compose（判定の1本）／payroll_close_lines（文）／payroll_close_notice_daily（cron 毎日 01:00 UTC）／
  my_payroll_close_notice・set_payroll_close_notice_dismissed（本人・退職者も）／payroll_close_notice_admin_preview・_test_send（管理者）

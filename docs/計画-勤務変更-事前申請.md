  先の日も選んで送れるが、送ると「報告（確認待ち）」として扱われる。注意書きは「欠勤は前もって／ほかはその日になってから」（2026-11-05）

## 残業の事前申請（お手本・すでに本番で動いている）
- overtime_reports.status：requested（事前申請）→ request_confirmed（事前受理）→ その日以降に本人が［実績を報告する］→ reported → confirmed。
  予定どおりなら受理なしで確定（overtime_confirm_as_planned・enforce_overtime_self_confirm）、違えば上長の確認。差し戻し returned
- 勤怠カレンダーとの二重：正社員は事前申請が自動でカレンダーに出る（calendar_overtime_events）。上長がカレンダーに入れる予定と重なると「お知らせが2通」になった（(334)(337)）

## 🚨 段0：今ある穴（先に塞ぐ・2026-11-05 シニアエンジニアの指摘を本番の定義で裏取り）
- shift_reports のポリシー applicant_insert の条件が submitted_by = auth.uid() だけで、**status を見ていない**。reviewer_confirm に WITH CHECK が無い。
  トリガーは trg_shift_report_part_only（正社員を止めるだけ）・trg_approver_not_on_leave（休職を見るだけ）
- → 本人が画面を通さず直接送れば、最初から status='confirmed'（受理済み）を入れられる。画面からはできない。2026-11-05 時点で不審な行は無い（受理待ち0・受理済み121）
- 事前申請を足すと「自分で予定を受理する」抜け道になるので、段3の前に塞ぐ
- 案：BEFORE INSERT/UPDATE の見張り（残業の enforce_overtime_self_confirm と同じ形）。
  INSERT は本人なら pending だけ（管理者・受理できる上長の代理は今までどおり）。UPDATE で confirmed／returned に変えられるのは、本人以外の受理できる人か管理者（service_role は通す）

## 案（2026-11-05 2体のレビュー1回目のおすすめ・ユーザー確認前）
1. 事前申請と報告は**日付で自動**：先の日＝事前申請、今日・過去＝報告。日付の下に「この日は先の日なので『事前申請』になります」・ボタン［この内容で事前申請する］
2. 上長が勤怠カレンダーに予定を入れた日は**事前申請を止める**（DB でも）。「この日は上長が予定を入れています（予定 早退 …）。当日になったら報告してください」。逆（上長がカレンダーに入れる）は止めない（急な欠勤のため）・注意だけ
3. 受理のあと：その日の勤務が終わるころから［実績を報告する］→［予定どおりでした］（受理なしで確定・サーバーの関数の中だけ＝印 app.sr_as_planned）／［予定と違いました］（時刻を直す→上長が確認）／［この日は予定がなくなりました］
4. 予定は**別の欄**（planned_segments／planned_location など）。実績で上書きしない（受理済みの変更の記録が埋まらない）
5. 表の丸：**予**＝事前申請 受理済み（残業と同じ字）。予のまま日が過ぎて報告が無い日は**未**
6. 最初の公開（社長・管理者だけ・feature_key shift_report_advance）では、シフト調整の相談・勤怠カレンダー・Google カレンダーにつながない
7. お知らせは通知設定の行を先に足してから（設定が無い＝全員に送る作りのため）
8. 給与の［表で見る］：事前受理のまま実績が無い日は灰色で合計に入れない

## 2026-11-05 2回目のレビュー（UI/UX・シニアエンジニア）で出たこと
- 段0 の穴はもっと広い：applicant_insert は applicant_id も見ない（受理の権限が無い人がほかの方の名前で入れられる）・reviewer_confirm に WITH CHECK が無い
  → 見張り enforce_shift_report_status（INSERT と UPDATE・migration 20261105231701）。本番で取り消しの試し11とおり（下）
- 欠勤は事前申請にしない（前もって出しても今までどおり報告）／遅刻・打刻忘れは先の日に選べない（前もって決まる遅れ＝「遅出」がパートの種別に無い）
- 言葉：勤怠カレンダーの分は「上長の予定」・本人の事前申請は「申請」（「予定」を2つ並べない）
- 当日の3つ：［申請どおりでした（確定）］［時間が違いました］［申請した変更はありませんでした］・上長は［事前申請を受理］
- 受理の前に当日が来たら、受理を待たずに報告できる（残業と同じ）
- 🚨 一意 (applicant_id, work_date) は取消済みも含む＝本人が取り消すとその日は二度と報告できない（今ある制限）。「変更はありませんでした」を cancelled にしない（同じ行を報告に切り替える）
- 予定の欄は事前受理の瞬間にトリガーが写す（furikae_planned と同じ）・log_application_change の WHEN に足す・事前申請の中身を actual_* に入れない
- 事前申請だったかは request_confirmed_at（差し戻しが事前か報告かも見分ける）
- 🐛 今ある不具合：retire_apply・staff_leave_reassign が status='pending' だけ（resubmitted が漏れている）
- 締めのお知らせ（payroll_close_compose）に「事前受理のまま報告が無い日」を出す・未報告の催促

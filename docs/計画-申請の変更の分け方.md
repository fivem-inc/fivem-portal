# 計画（案）：申請を出したあとの「変更・取消」をだれが受けるか（2026-10-26）

## きっかけ
- 振替休日に［休む日を出勤に変える（休日出勤は残す）］を作った（2026-10-26・上長の受理で自動で変わる）。
- ほかの申請の「変更」は、確定のあとは管理者（経理）への［📩 修正を依頼］［取消を依頼］で、管理者が手で直す。
- ユーザーから「ほかの変更（残業など）と同じか？ 管理者の操作・上長の判断・本人の変更を整理して、どれがいちばんいいか」。

## 今の決まり
| 申請 | 本人が自分で直せる | 上長 | 管理者 |
|---|---|---|---|
| 残業申請 | 申請中・事前申請 受理済み・差し戻し（［内容を修正する（取り消して再申請）］・取消）。支給月17日まで | 受理・差し戻し（事前と実績の2回） | 実績報告済み・確認済みの修正・取消（本人の修正依頼・取消依頼を受けて［📋修正］／取消） |
| 休暇申請 | 申請中・差し戻し | リーダー→マネージャー→経理→社長の順に受理 | 受理のあとの修正・取消（本人の依頼を受けて） |
| 勤務変更（パート） | 確認待ち・再提出・差し戻し | 確認・差し戻し | 受理のあとの修正・取消（本人の依頼を受けて） |
| 振替休日（2026-10-26〜） | 休む日・振替元の日のどちらかが来るまで取消 | 受理・実績の確認／［この日は勤務しませんでした］の判断（出勤に戻す・有休などへ）／［休む日を出勤に変える］の受理 | どちらかの日が来たあとの取消（本人の取消依頼を受けて） |

- 修正依頼・取消依頼は管理者（経理）にだけ届く（DB の submit_correction_request）。管理者の［📋修正］は時間帯・種別・日付などを直せるが、振替元の時刻は直せず、1つの申請を2日分に分けることもできない。

## 案
- **案1（今のまま・こちらのおすすめ）**：考え方を「上長＝これからの勤務の中身を決める（休む・出勤・時間・場所＝シフト調整に響く）／管理者＝済んだ記録の誤りを直す（打ち間違い・確定後の訂正＝給与に響く）／本人＝受理の前は自分で、あとは依頼」にそろえる。振替休日の変更はいつでも上長。
- **案2（ほかとそろえる）**：確定の前は上長、確定のあと（振替元の実績が確定したあと）は管理者に届く。管理者もボタン1つで同じように自動で変えられる。
- **案3（案1を全申請に広げる）**：休暇申請なども、受理のあとでも「これからの予定の変更」は上長に届くようにする（今は管理者）。

## 見てほしいこと
- 本人・上長・管理者（経理）のそれぞれにとって、どれがいちばん迷わず・手間が少なく・間違いが起きにくいか
- 給与（17日の締め）・シフト調整・お知らせ・権限・監査（だれが何を変えたかの記録）への影響

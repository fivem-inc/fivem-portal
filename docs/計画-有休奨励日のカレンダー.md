# 計画：有休奨励日の休みを Google カレンダーに出す（2026-10-19）

## きっかけ
- 有休奨励日（10/31）に回答して休む方が、Google カレンダーに1人も出ていなかった（24件・有休19・調整休3・その他2）。
- 原因：奨励日の回答は DB の関数 `answer_encouragement_day` が受理済みの休暇（reason＝'【有給奨励日】'）を作るだけで、
  カレンダーへ送る係（共用の Edge Function `gcal-sync`）を誰も呼んでいなかった（作り忘れ・決めた記録なし）。種類に関係なく全部出ていなかった
- 勤怠カレンダー（アプリ）には出ているが、見ていない人もいる。

## ユーザー確定（2026-10-19・一問一答）
- 出し方は管理者が設定で選ぶ：**出さない／まとめて1件／1人ずつ**（最初は まとめて1件）
- 出す休み：**有休・調整休・その他**を選べる（最初は全部）。その他＝回答の「定休日」「その他（休む）」
- 名前：**出す／出さない（人数だけ）**（最初は出す・まとめて1件のときだけ効く）
- まとめて1件の形（案2・下の1行は入れない＝勤怠カレンダーを見られない人もいるため）：
  ```
  題名：有休奨励日
  本文：
  【有休 19人】
  名前、名前、…
  【調整休 3人】
  名前、名前、名前
  【その他 2人】
  名前、名前

  合計 24人
  ```
  0人の種類の見出しは出さない。名前を出さない設定のときは見出しだけ
- 予備：回答・修正・設定の保存でその場で作り直す（本体）＋**毎晩、カレンダーと記録のずれを直す**（ア）
- ふだんの休暇（奨励日の回答でない休暇）は今までどおり1人ずつ（この設定は効かない）

## 専門家2体のレビュー（2026-10-19）で直したこと
- 🚨 予定を消すとき、作ったときのカレンダー（gcal_events.calendar_id）から消す（今の gcal-sync は「今選ばれているカレンダー」から消していた。本番／テストを切り替えたあと本番の予定が残る穴・既存の delete / upsert も直す）
- テストのカレンダーへの切り替えで試さない（全員の同期先が変わる）。代わりに **dry_run**（Google を呼ばず、作る・直す・消すの一覧と本文を返す）で確かめ、本番では 10/31 だけを作る
- まとめの予定は **中身を直す（PATCH）だけ**（消して作り直さない）。1人ずつのときは **差分だけ**（無いものだけ作る・余ったものだけ消す）
- 作り直しは「状態を変えたあとに target_date を渡して、今の状態から」にそろえる（delete の前に呼ぶ・その休暇を除く、はやめる）。
  奨励日の休暇かは reason だけでなく「その日に奨励日があるか」でも見る
- 掃除：その日の 'leave' の予定のうち、休暇の行が無い・受理済みでない・その日を含まない 奨励日の休暇のものは消す（日付を変える修正 LeaveEditModal も含む）
- 奨励日そのものを消したあとも、まとめの予定は日付で探して消す
- 日付を指定しない作り直しは、管理者と service だけ
- 本文に「その他」のメモ（本人が書いた文）は出さない。名前の全角スペースは半角に。並びは毎回同じ（名前の順）。「今日」は日本時間
- 設定の画面（UI/UX）：選択肢は説明つき（「まとめて1件（その日に予定1つ・中に名前）」「1人ずつ（ふだんの休暇と同じ形）」）／
  効かない設定は隠さず薄く（出さないのときは下の2つ・1人ずつのときは名前）／出す休みが0個なら保存できない／
  保存の前に「いまの連携先（本番）で、10/31（24人）の予定を作り直します。過去の日は変わりません」／終わったら件数・失敗したら［もう一度作り直す］／
  「見え方」の箱は次の奨励日の実際の人数で・選んだ内容ですぐ変わる。絵文字は使わない

## 設計
### 設定
- `app_settings` の `gcal_encouragement` ＝ `{ "mode": "off" | "summary" | "each", "types": ["有休","調整休","その他"], "names": true }`
- 無いとき・読めないときは `{ mode: "summary", types: 全部, names: true }`
- 管理画面 → 通知設定 →「Google カレンダー」の下に「有休奨励日の休みの出し方」（［変更する］→［保存］・SaveBar）

### gcal-sync に足すもの（共用・場所予約の担当に連絡）
- `action: 'sync_encouragement'`（`target_date` 省略可＝これからの奨励日すべて・省略は管理者と service だけ）・`dry_run` 可
- 既存の upsert / delete（source_type='leave'）で、奨励日の休暇なら sync_encouragement（その日）に回す
- 予定を消すときは gcal_events.calendar_id を使う

### 呼ぶところ（画面）
- 奨励日に回答したあと（App.tsx・LeaveRequest.tsx）→ その日
- 管理画面で奨励日の回答を直す・消す・奨励日を消す（LeaveRequestsTab）→ その日
- 設定を保存したとき → 日付なし
- 失敗しても回答・修正は止めない（毎晩の作り直しで拾う）

### 毎晩
- cron（service）で `sync_encouragement`（日付なし）。差分だけなので、変わりの無い日は Google をほぼ呼ばない

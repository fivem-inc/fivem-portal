# 計画：打刻の確認を「申請がある日」にも送れるようにする

状態：計画（未着手）。2026-10-13 経理担当の意見を受けて、社長（晃平さん）が一問一答で決めた。
見本の画像（名前なし・リポジトリの外）：配布資料/打刻の確認_*.png

## 1. 困っていること（経理担当の意見）
- 管理画面 → 残業 →「打刻の確認」で、すでにアプリから申請がある日は「⚠️ この日は既に記録があります」になり、確認を送れない
- 申請の中身が打刻とずれているとき、今は差し戻すしかない。本当は「申請の通り」で済むことも多く、返事だけもらえればよい
- 確認を送る場所（画面）が日によって変わるのも困る → すべての日に打刻の確認を送れるとよい

- 取消：管理画面の［取消］（Edge Function overtime-approve の cancel）

## 3. 決まったこと（ユーザー確定 2026-10-13）
1. 申請がある日にも打刻の確認を送れる。経理の画面にその日の申請の中身（例「事後報告 21:00〜22:00・確認待ち」）を出す
2. **申請がある日**の本人の答え
   - 申請の通りです（新しい記録は作らない。その申請と確認を結び付ける）
   - 時刻が違います（その場で正しい開始・終了を入れる。最初は申請の時間が入っている。［シフトの終わり＝残業なし］ボタン。理由は「ひとこと」）
   - 思い出せない・その他（経理に相談）
3. **申請がない日**の本人の答え：業務をしていました／**定時でした（打刻が遅れただけ）**（今の「業務は終わっていました」）／思い出せない・その他
4. 経理の画面：「申請」「本人が入れた正しい時間」「打刻」「ひとこと」を並べ、［この時刻で申請を直す］
   - 残業がなくなる答えなら［この申請を取り消す（定時にする）］
   - 受理済みでも直せる。前の時刻は履歴に残る。納得できなければ押さずに聞き直せる
5. 時間を入れる画面のいちばん上に黄色い枠：シフト・出している申請・打刻・経理のひとこと
   - 「業務をしていました」から開く事後報告は、終わりに退勤の打刻を最初から入れておく（違えば直す）
6. 差の表し方：「申請 ＋1:00 → 正しい時間 ＋0:30」。経理の画面の行名は「本人が入れた正しい時間」
7. 今の不具合2つもあわせて直す（worked のあと link されない／申請がある日の打刻ズレを黙って飛ばす）

## 4. 作り方の案（レビュー対象）
### DB（migration 1本）
- overtime_clock_inquiry_days
  - answer の check に as_reported（申請の通り）・time_differs（時刻が違う）を足す
  - existing_report_id（送った時点のその日の手動申請・サーバーで求める）
  - answer_segments jsonb（本人が入れた正しい時間 [{start_min,end_min}]）
  - resolved_at／resolved_by（経理が直した・取り消した）
- send_overtime_clock_inquiry（🚨 本番の実定義から起こす）
  - その日に取消以外の manual 申請があれば existing_report_id に入れる。その日は締め後の許可を付けない（新しく作らないため）
- answer_overtime_clock_inquiry（🚨 本番の実定義から起こす）
  - 新しい答えを受け付ける。existing_report_id がある日は as_reported／time_differs／unknown だけ、無い日は worked／not_worked／unknown だけ
  - as_reported・time_differs の日は result_report_id に既存の申請を結び付ける
  - 経理あての要約文に新しい答えを足す
- 経理が「直した」「取り消した」を記録する関数（管理者だけ）＝resolved_at を入れる
- 申請が出たら確認と結び付けるトリガー（overtime_reports の insert で、同じ人・同じ日の worked の確認日に result_report_id を入れ、許可を閉じる）→ 不具合1を DB で直す

### 画面
- OvertimeClockInquiryPanel：既存申請の除外をやめ、申請の中身を表示。答えの一覧に新しい答え・本人が入れた正しい時間・差・［この時刻で申請を直す］（既存の OvertimeEditModal を、本人の時間を入れた状態で開く。修正の理由に「打刻の確認の回答より」）／［この申請を取り消す（定時にする）］（既存の取消）
- ClockInquiryResponse：日ごとに existing_report_id の有無で選択肢を切り替える。時刻が違うの入力欄（TimeInput・申請の時間で初期化・シフトの終わりボタン）。黄色い枠。not_worked の打刻ズレ作成で失敗したら知らせる（不具合2）。言葉「定時でした（打刻が遅れただけ）」
- OvertimePage の onReportOvertime：下書きの終わりに退勤の打刻を入れる＋黄色い枠を出すための情報を渡す
- FAQ・注意事項：打刻の確認の説明があれば直す

## 5. 守ること
- RPC は本番の実定義から起こす（pg_get_functiondef）。新しい関数は revoke … from anon と has_function_privilege で確かめる
- 通知の新しい種類は作らない（既存の overtime:clock_inquiry／overtime:clock_inquiry_answered を使う）
- `.update()` は件数を見る。`rpc` は error を見る
- 配色・ボタンは lib/buttonStyles.ts の決まり

## 6. レビュー（UI/UX・シニアエンジニア 2026-10-13）のあとに決まったこと（ユーザー確定）
- 「時刻が違います」で入れる時間は「実際の勤務時間（出勤〜退勤）」。最初は申請の時間。差（申請 ＋1:00 → 正しい時間 ＋0:30）は申請の normal_shift と同じ休憩の計算で出す
- 近道ボタンは2つ：［退勤の打刻（22:30）］［シフトの終わり＝残業なし］
- 経理の画面は日ごとのカード＋札（対応待ち／直しました／取り消しました／このまま）。［直さずに終える］［この日をもう一度聞く］を置く
- ［この申請を取り消す（定時にする）］は新しい関数で「申請を取り消す＋打刻ズレ（定時）を作る＋履歴」を1回で（今の取消は受理済みを取り消せない・管理画面の［取消］は履歴が残らない）
- 経理が直したら本人に「打刻の確認のお答えのとおり、21:00〜21:30 に直しました」（通知の種類は増やさず文面だけ）
- anon から呼べた関数4つ（answer_overtime_clock_inquiry・link_clock_inquiry_result・cancel_own_clock_only_report・oci_can_view）を外す
- 段階：0（不具合2つ＋anon）→ 1（本人の答え方・経理の表示）→ 2（経理の操作）→ 3（下書きに退勤の打刻・FAQ）

## 8. 申請の状態ごとの答え（ユーザー確定 2026-10-13・段階1で作る）
| その日の申請 | 本人が選べる答え |
|---|---|
| なし | 業務をしていました／定時でした（打刻が遅れただけ）／思い出せない・その他 |
| 実績報告済み・受理済み | 申請の通りです／時刻が違います／思い出せない・その他 |
| 事前申請だけ（実績報告がまだ） | 予定どおり勤務しました（実績を報告します）／時刻が違います（実績報告の画面を正しい時刻で開く）／その他 |
| 差し戻し中 | 申請を直して出し直します／その他 |
| 終日（振替休日・欠勤・調整休） | 申請の通りです／その他 |
| 休暇の日 | 経理の画面で「休暇の日」と出し、送る前に気づけるようにする |
- 答えの選択肢は「本人が答える時点の申請」で決め、サーバーでも答えを受け取るときに見直す
- 言葉は「勤務」にそろえる（「予定どおり勤務しました」）

## 3. いまの作り（調べた結果）

- `/admin` は `App.tsx` の `AdminPage` が `isAdmin` だけで判定。ナビの「⚙️ 管理」も `isAdmin` だけ
- `AdminPanel.tsx` のタブは `TAB_GROUPS` に固定。**タブごとの権限は無い**。`?tab=` を直接打てばどのタブにも入れる
  （`AdminPanelContext.tsx` の `initialTab` は `ADMIN_TABS` に含まれるかだけを見る）
- 管理画面を開くと、どのタブかに関係なく `fetchUsers()` と `fetchLeaveRequests()` が走り、承認待ちのバッジを出す
- 各タブの書き込み先と今の決まり（本番の RLS・関数の中身を読んで確認）

| タブ | 書き込み先 | 今の書き込み権限 |
|---|---|---|
| グループ | `profiles.group_names`（所属）／`master_options`（category='group'） | 管理者だけ（`profiles` の ALL・`master_options` の I/U/D） |
| 通常シフト | `weekly_shift_patterns`（画面から1行ずつ。RPC なし・トランザクションなし） | 管理者だけ（`patterns_admin_all`） |
| リマインド設定 | `board_scheduled_reminders`／`reminder_days_settings` | 管理者だけ |
| FAQ管理 | `faq_topics`／`faq_answers`／`faq_answer_targets`／`faq_topic_relations` | `can_edit_faq()`＝管理者 or `profiles.is_faq_editor` |
| お知らせ | `announcements`（`lib/announcements.ts`）＋ Edge Function `announcement-notify` | 表は `is_admin()`・関数も admin だけ |
| 安否確認 | `safety_check_templates`／Edge Function `safety-check-send`／RPC `submit_safety_response_proxy`／RPC `delete_safety_check` | 定型文・発信・代わりの回答は **もともとマネージャー以上**。削除だけ管理者 |

- 読み取りは概ね足りている：`profiles` は全員読める／安否の発信・回答はマネージャー以上が読める／`announcements`・`app_settings` は全員読める
- 🚨 リマインド設定が読む `board_channels` は「メンバー or 作成者 or 管理者」しか読めない（2026-09-14 実測）。
  **マネージャーは自分が入っていないチャンネル宛てのリマインドを選べない**＝画面の選択肢が欠ける。
  ① でリマインドを開くなら、チャンネル一覧を読む手段（`can_manage_admin_tab('scheduled_reminders')` の人は全チャンネルの id と名前だけ読める関数など）が要る
- ✅ FAQ の集計 RPC `faq_public_event_summary` は **SECURITY INVOKER**（呼んだ人の権限で読む・2026-09-14 実定義で確認）。
  読む表 `faq_public_event` の RLS が `can_edit_faq()` なので、**`can_edit_faq()` を広げれば集計も見られる**（関数を別に直す必要はない）

## 4. 設計（① 入口）

### 4-1. 設定の持ち方
- `app_settings` の key **`manager_admin_tabs`**＝マネージャー以上に開くタブの配列（例 `["faq","scheduled_reminders"]`）。
  既定は空配列＝**全部オフ**。読みは全員（既存の RLS）・書きは管理者（既存の RLS）
- 🚨 **DB 側でも同じ設定を見る**：新しい関数 `can_manage_admin_tab(p_tab text)`＝
  `is_admin() or (is_manager_plus() and manager_admin_tabs に p_tab が入っている)`。
  各タブの書き込みの決まりをこれで広げるので、**管理者がチェックを外せば DB の書き込みも止まる**（画面だけの制限にしない）
- 🚨 **「PC だけ」は画面の制限**。DB は端末を見分けられない（スマホから API を直接叩けば書ける）。ユーザーに説明済みの前提として明記する

### 4-2. 画面
- 新しい hook `useManagerAdminTabs()`（`app_settings` を1回読んで共有・`useRoles` と同じ形）
- 「管理画面に入れる」＝ `isAdmin || (isManagerPlus && isPointerDevice() && 開くタブが1つ以上)`
  - `App.tsx` の `AdminPage` の判定と、`NavBar` の「⚙️ 管理」ボタンの判定をこれにする
    （🚨 NavBar は15か所から呼ばれている。props を増やさず、NavBar の中で hook を呼ぶ）
- `AdminPanel.tsx`：管理者でなければ `TAB_GROUPS` を「開くタブ」だけに絞る（PC の3段・スマホのセレクトの両方）
- `AdminPanelContext.tsx`：`initialTab` と `setActiveTab` も「開くタブ」に含まれるかを見る（URL 直打ち対策）。
  管理者でなければ `fetchUsers`/`fetchLeaveRequests` の常時読み込みとバッジを止める（グループのタブを開いたときだけ `fetchUsers`）
- タブの中の出し分け（管理者でない人）
  - グループ：グループの追加・名前変更・削除のボタンを出さない。所属の追加・外すは新しい RPC 経由
  - FAQ：`canManageEditors` は管理者だけ（今のまま）
  - 安否：削除ボタンを出さない
  - 通常シフト（②）：残業管理の中の「通常シフト」だけを出す（受理済み一覧・打刻・締め後の許可・会社カレンダー・設定は出さない）
- 「権限管理」タブの末尾に「マネージャー以上に開く管理画面のタブ」（新しい部品・チェックボックス）。
  `FeaturePermissionsTab.tsx` には import と1行だけ足す（自動ログアウトの設定枠と同じ形）

### 4-3. DB（① で入れるもの）
| 対象 | 変更 |
|---|---|
| 共通 | `can_manage_admin_tab(text)`（SECURITY DEFINER・anon 実行不可） |

- 🚨 `can_edit_faq` など既存関数を変えるときは `pg_get_functiondef` から起こし、機械で突合
- 取り消し版で「管理者／マネージャー（タブON）／マネージャー（タブOFF）／リーダー／パート」になりすまして書き込みを試す

### 4-4. 出す順
DB（関数・RLS）→ Edge Function（announcement-notify・🚨 deploy 前に git pull）→ 画面。
最初は全部オフなので、出した瞬間に誰の画面も変わらない。管理者が確かめてからタブを1つずつオンにする。

## 5. 設計（② シフトの一括編集・概要のみ。① のあとで詳しく決める）

- 「通常シフト」に［修正］→ 表に出ている全員×月〜日を一度に編集できる表 → 適用開始日 → 前日に効いている版と違うマスを赤 → ［保存］
- 保存は **SECURITY DEFINER の RPC 1回**で全員分を書く（途中で失敗したら何も残らない）。Excel取込も同じ RPC に乗せ替える
  （今は取込も1人ずつの編集も、画面から1行ずつ書いていてトランザクションが無い）
- 「使い始め」は権限管理のスイッチ（オフの間は今の1人ずつの編集と取込だけ）
- 🚨 `weekly_shift_patterns` は同じ人×同じ曜日で期間が重なる行を DB が禁止（exclude 制約）。締め→入れる の順は RPC の中で守る
- 影響先：`sync_overtime_from_leave`（時間外調整休）／OvertimePage の通常シフト／シフト調整の候補／ShiftDirectoryPage ほか

### Edge Function `announcement-notify`

- 送る相手を読めなかったときだけ印を戻す。push の失敗・メールの失敗数を返す（`push_failed`／`email_failed`）

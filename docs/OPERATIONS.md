## 2. 毎日どこで何が動いているか

### このPCで動くもの（PCが起動していないと動きません）

| 時刻 | 何が動くか | 保存先 |
|---|---|---|
| **12:00**／ログオン時 | PC内のファイルのバックアップ（`.env` など4つ） | NAS `…\社内サイト\` |
| **12:30** | **Supabase（データベース）のバックアップ** | NAS `…\社内サイト\db-backup\` |

- どちらも **PCが起動していないと動きません**
- 12:30 にPCが止まっていた場合、DBのバックアップは**次に起動したときに自動で実行**されます
- 1回あたり約30秒・約314KB

### Supabase（クラウド）側で動くもの ＝ PCの電源に関係なく動きます

| いつ（日本時間） | 何が動くか |
|---|---|
| 毎分 | プッシュ通知の配信 |
| 5分ごと | 連絡板の予約送信／各種リマインドの見張り（有給奨励日・未読・定期・安否確認） |
| 毎日 **9:00** | お知らせの期限リマインド／残業の実績未報告／残業の目安超過のお知らせ |
| 毎日 **深夜3:00** | 既読から30日たった通知の削除 |
| 毎日 **深夜3:30** | cron実行履歴の掃除（放置するとDBの容量を食いつぶすため） |
| 毎週 **月曜9:00** | ストレージ・データベースの容量チェック（8割を超えると警告）／管理者の設定もれ通知 |

※ 全部で13個。すべて動作中です。

## 3. バックアップが正常か確かめる方法

### ⚠️ 日付では判断できません

NAS上のファイルの日付は、次の理由で「いつバックアップされたか」を表しません。

- **作成日時** … 上書きでは更新されず、初回のまま止まる
- **更新日時** … コピー元の日時がそのまま引き継がれる

### 正しい確認方法

NAS の `…\社内サイト\db-backup\db_backup_log.txt` を開き、**いちばん下**を見てください。

**正常なとき** — 最後が `===== 正常終了 =====` で、その手前にこれらが並びます。

```
検証OK: RLSポリシー 193 本
検証OK: auth.users あり
検証OK: データダンプは最後まで完了
検証OK: 暗号化ファイルを開けることを確認
OK: NAS に保存しました （314208 バイト）
===== 正常終了 =====
```

**異常なとき** — `ERROR:` の行や `===== 異常終了 =====` が出ます。

その日は保存されていませんが、**中身の怪しいもので上書きしない作りなので、前日までのバックアップは無事です**。
ERROR の行に理由が書いてあるので、その文面を添えて相談してください。

## 4. 保管されているもの

| 場所 | 中身 | 世代 |
|---|---|---|
| `db-backup\daily\` | 毎日のバックアップ | **14世代**（2週間ぶん） |
| `db-backup\monthly\` | 毎月1日のバックアップ | **12世代**（1年ぶん） |

## 5. 🔑 パスワードの管理（いちばん大事）

バックアップは **7-Zip の AES-256 で暗号化**しています。ファイル名の一覧も暗号化しているので、
保存先を開いても中に何が入っているかは分かりません（保存先が全社員の見える共有フォルダのため）。

- パスワードは **32文字**。**紙2枚**（社長用・経理責任者用）が保管されています
- PCの中にも保存されていますが、**このPC・このアカウントでしか復号できない**形式です
- 🚨 **PCが壊れると、PC内の分は二度と復号できません。紙の控えが唯一の鍵になります**
- 🚨 **年1回、封を開けて読めるか確認してください**（インクの退色・紛失に気づくため）

### やってはいけないこと

- パスワードをメール・チャット・LINEに貼らない
- 2枚を同じ場所に保管しない
- パスワードを作り直さない（作り直すと、**それ以前のバックアップは永久に開けなくなります**）

## 6. 困ったときは

| 症状 | どうするか |
|---|---|
| ログが何日も増えていない | タスクが動いていない可能性。PowerShell で `Get-ScheduledTask -TaskName 'BackupFivemSupabaseDB'` |
| `異常終了` が続く | ログの `ERROR:` の行をそのまま伝えて相談 |
| いますぐ手動で取りたい | PowerShell で `Start-ScheduledTask -TaskName 'BackupFivemSupabaseDB'` |
| PCが壊れた | [DISASTER-RECOVERY.md](DISASTER-RECOVERY.md) の「3. 新しいPCでの復旧手順」 |
| Supabaseを失った | 同「5. Supabase のプロジェクトを失った場合」「6. 復元する」 |

---

## 7. この仕組みで守られないもの

| 対象 | 理由 | 今どうしているか |
|---|---|---|
| レシート・見積書の**画像** | データベースの中に無いため | **紙の原本が正式な保存書類**（7年保管）なので、紙で担保 |
| Edge Function の設定値28個 | Supabaseから読み出せない仕組み | 失った場合の再取得手順を手順書に記載済み |
| プッシュ通知の秘密鍵 | 同上・控えが存在しない | 失った場合は全員に通知の再設定を依頼（手順書に記載） |

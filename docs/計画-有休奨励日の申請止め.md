# 計画：有休奨励日の休みは「奨励日の回答」から出してもらう（2026-10-19）

## きっかけ
- 10/31（有休奨励日）に、回答の対象の人が次のように出していた。
  - 奨励日の回答（有休）とは別に、休暇申請の有休を出した（受理の途中）
  - 奨励日の回答（有休）のほかに、残業申請の時間外調整休も出した（両方受理済み）
- 奨励日の休みは、経理が回答の受付を作り、回答から休暇を作る流れになっている。ほかの申請から出されると、2重になり、Google カレンダーのまとめにも入らない。
- 2026-10-19 に、休暇申請と残業申請の終日の休みが同じ日に重ならないようにした（トリガー trg_day_off_conflict_*）。今回はそれとは別で、「奨励日は回答から出す」を決まりにする。

## ユーザー確定（2026-10-19・一問一答）
- **止めるのは申請**（カレンダーの見え方の話ではない）。
- **いつから止めるか**：年間カレンダー（company_calendar.kind = 'work_on_closed_encouraged'）でその日が奨励日になった時点から。
  - 経理が回答の受付（paid_leave_encouragement_days）を作る前：**正社員全員**を止める（下の「止めない人」は除く）
  - 受付を作った後：**その受付の対象者（paid_leave_encouragement_targets）だけ**を止める。対象外の人はふつうに申請できる
- **止めない人**：管理画面で選ぶ（役員など）。最初に入れるのは、会長・取締役1名、社長、共用のアカウント2つ（「管理者」「Q&A管理専用」）。
  受付を作る画面で、対象のチェックの初期値にも使えるようにする（任意）。
- **止める申請**（おすすめの案・モックで提示）：
  - 休暇申請の「有給休暇」「バースデー休暇（有給）」
  - 残業申請の「時間外調整休」
- **止めない申請**：慶弔休暇・振替休日・欠勤・遅出／早退・残業・勤務時間変更・勤務地変更（イベントで出勤する日など）。
  慶弔は証明、振替は振替元の日、欠勤は上長の確認が要るため、ふつうの申請から出してもらう。
- **回答の「その他」を2つに分ける**：
  - 「その他（出勤する）」…今までどおり休暇は作らない（イベント・会議などで出勤）
  - 「その他（慶弔・振替休日・欠勤など）」…回答だけ残し、休暇は作らない。「ふつうの申請から出してください」と案内する
    （作ってしまうと、あとで出すふつうの申請と重なり、重なり止めで止まるため）
- **回答のあとで変わったとき**（休む→出勤、出勤→休む、当日の欠勤など）：今までどおり経理が管理画面で回答を直す（休暇もカレンダーも作り直される）。
- **イベントでその日がまるごと奨励日でなくなったとき**：年間カレンダーのその日を直せば、止めるのも解ける。

## 2体のレビュー（2026-10-19）のあと、一問一答で決まったこと（これが最終）
- 止める申請：休暇申請の **有給休暇・バースデー休暇（有給）**（バースデー休暇はアプリの中で別に数えていない＝有給休暇の行に合算・本番の使用は0件）、残業申請の **時間外調整休**。
  慶弔・振替休日・欠勤・休暇申請の「その他」・遅出／早退などは止めない
- 止めない人：管理画面の有休奨励日の欄「対象外の方（役員など）」（app_settings 'encouragement_exempt'）。初めは役員2名と共用のアカウント2つ
- 通すもの：奨励日の回答・管理画面の回答の修正（DB の印 app.enc_answer）／管理者・社長の操作／cron。🚨 休暇の理由欄の印（'【有給奨励日】'）では通さない（本人が書けばすり抜けるため）
- 止めたときの文（DB の encouragement_block_message 1か所）：
  - 受付前：「M/D（曜）は有休奨励日のため、この日の有給休暇・時間外調整休はここでは申請できません。回答のお知らせが届いたら、「有休奨励日の回答」から回答してください。お知らせが届かない場合は、経理へご相談ください。」
  - 受付後（未回答）：「M/D（曜）は有休奨励日のため、この日の有給休暇・時間外調整休はここでは申請できません。「有休奨励日の回答」から回答してください。」
  - 回答済み：「M/D（曜）の有休奨励日は回答済みです。内容を変える場合は、経理へご連絡ください。」
- 知らせるタイミング：日付（と種類）を選んだ時点で赤い枠（休暇申請・残業申請の終日の休み）。最後は送る前の確かめと DB のトリガー
- 回答の選択肢：有給休暇／時間外調整休（前の「欠勤（調整休）」）／定休日／出勤する（イベント・会議など）／ほかの休みを申請する（慶弔・振替休日・欠勤）。
  4・5 は内容が必須。5 は休暇を作らず「慶弔休暇は「休暇申請」、振替休日・欠勤は「残業申請」から、別に申請してください。」
- 回答の画面はホームと休暇申請の2か所のコピーを1つに（components/EncouragementAnswerModal）
- その日にほかの休暇（取消・差し戻し以外）がもうある人が、休暇を作る回答をしたら断る（「経理へご相談ください」）。経理の受付の確かめの画面に「すでに休暇・終日の休みを申請している方」を出す
- 締め切り後の回答は今どおり受け付ける。回答を直せるのは今どおり経理だけ（管理画面の修正は admin_set_encouragement_answer 1本で回答と休暇をまとめて直す）
- 社内FAQ：奨励日の回答の選び方を説明した項目は無い（直す所なし）

## 止めたときの文（モック・確定前）
- 受付を作った後：「10/31（土）は有休奨励日です。この日に休む場合は、休暇申請ではなく「有休奨励日の回答」から申請してください。」
- 受付を作る前：「10/31（土）は有休奨励日です。回答のお知らせが届いたら、「有休奨励日の回答」から申請してください。」

## 作り（案）
- DB：判定の関数1本（例 encouragement_block_message(user, date, side, kind)）。年間カレンダー・受付・対象者・止めない人を見て、止めるなら文を返す。
  トリガー（leave_requests／overtime_reports の insert と、日付・種類・状態を変える update）で止める。今あるデータは触らない。
  - 奨励日の回答が作る休暇（reason＝'【有給奨励日】'）・管理画面の回答の修正・休暇の調整休の写し（entry_type='leave_auto'）は通す
  - 取消・差し戻し・却下にする update は止めない
  - 送る前の確かめは今の my_day_off_conflict と同じ形（画面が先に聞き、最後は DB が止める）。文は DB で作り、画面は出すだけ
- 止めない人：app_settings に user_id の一覧（管理画面で選ぶ）か、profiles に印の列。
- 回答の選択肢：answer_encouragement_day の p_choice に 5（その他・慶弔／振替／欠勤）を足す（5 は休暇を作らない・内容は必須）。管理画面の回答の修正にも同じ選択肢。
- 管理画面の回答状況の一覧に、その他のメモ（「イベント」など）を出す。

## 決まっていないこと・別の話
- 回答の「調整休」が残業時間から引かれていない（15件）。回答の調整休を残業申請の時間外調整休として作るべきかは、経理の答え待ち。
- 経理が受付を作るのが遅れた場合、その間はだれもその日の有休を出せない（回答もできない）。

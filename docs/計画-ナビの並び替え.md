# 計画：上のナビの並び替え（2026-10-17 ユーザー確定・一問一答）

作るのはレビュー（UI/UX・シニアエンジニアの2体）のあと。

## 決まったこと
1. **管理者**：管理画面 → 権限管理 に「ナビの並び」。全員の初めの並びを↑↓で決める。
   「スタッフが自分で並べ替えできる」のオン／オフもここで切り替える（オフ＝全員が管理者の並び）。
2. **本人**：オンのときだけ「設定」に「上のナビの並び」。↑↓で並べ替え・［管理者の並びに戻す］。
   並びはアカウントに保存（スマホとパソコンで同じ）。
3. **並べ替えだけ**。ボタンを隠す機能は作らない（「ボタンがなくなった」という問い合わせを避ける）。
4. **固定**：ホームはいつも先頭・FAQ はいつも端。管理者の ⚙️ は今までどおり。
   入社・退職・休職の手続きのボタン（マネージャー以上と管理者）は並べ替えできる部分に入れ、初めは FAQ の手前。
5. 使う権限のない機能は今までどおり出ない（並びを持っていても、出すかどうかは権限が先）。
6. あとで新しい機能が増えたら、自分で並べた人にはその人の並びの最後に足す。

## 作り方のたたき台（レビューで直す）
- 管理者の並びとオン／オフ：app_settings（例：`nav_order` ＝ キーの配列・`nav_order_personal` ＝ true/false）。
- 本人の並び：profiles に1列（キーの配列・空＝管理者の並び）。
- ナビは App.tsx の NavBar（ボタンを1つずつ書いている）→ ボタンを「キー → 中身」の表にして、並びの配列の順に描く形に直す。
  🚨 App.tsx は2人で共用。場所予約のボタンも並べ替えの対象になる（場所予約の担当に先に連絡する）。
- 並びを読む前に描くと並びが一瞬変わるので、端末に覚えておいた並びで先に描く（読み終わったら差し替える）。

## レビューの結果（2026-10-17）
- 🚨 今の先頭のボタンは「🏠 交通費」（/）で、交通費を使える人にしか出ない（App.tsx 1095行あたり）。「ホームはいつも先頭」をどう作るか決める必要がある。
- ナビは15か所で描いていて、ページを移るたびに付け直される。管理者の並びは useFeaturePublished（app_settings）、本人の並びは loadProfileOnce と authCache に入れて読み直しを増やさない。
- 本人は profiles を直接更新できない→ RPC set_my_nav_order（知らないキー・長さを弾く・anon を revoke）。
- ボタンの表（キー・名前・表示の条件・数字）は App.tsx から lib に出し、管理画面・「設定」と共用する。
- 「設定」の一覧：上に「上にあるものほど、ナビの左に出ます」／↑↓は 44px 以上・動かした行を少し光らせる・両端は押せない／戻すボタンの名前は「最初の並びに戻す」。
- 管理者がオフにする・初めの並びを変えるときは、自分で並べている人数を出す。新しく足された機能には「新しく追加」の印。

## 追加で決まったこと（2026-10-17・ユーザー確定）
- ナビの形は今のまま（下のタブ・上の帯・ホームをボタンの一覧にする案は見送り。モックで比べたうえで「いまはそのままで並び替え」）。
- 🏠 は誰にでもいつも先頭。交通費を使う人は「🏠 交通費」、使わない人は「🏠 ホーム」（ホームの交通費のフォームは今までどおり使う人だけ）。
- スマホ：ページのいちばん上では**2段**で全部のボタンを見せる。下へスクロールしたら**1段**に縮める（今と同じ横に流す形・隠れたボタンの数字は赤い「›」）。上へ少し戻すか、いちばん上に戻ったら2段に開く。
  縮むときに中身を上下に動かさない。文字の大きさ「特大」で2段に入りきらないときの形は作るときにモックで決める。パソコンは今のまま（折り返し）。
- **ベルとアカウントの丸はいつも1段目の右端に固定**（2段のときも1段のときも）。管理者の「確認」（役職プレビュー）も右側。機能のボタンはその左の残りの幅に並べる。

## 試してから広げる（2026-10-17・ユーザー指示）
- まず社長で試したい。管理者が管理画面で、新しいナビの機能をそれぞれ **オフ／選んだ人だけ／全員** に切り替えられるようにする。
  - 「2段（スクロールで1段に縮む）」の切り替え
  - 「並べ替え（本人が自分で並べる）」の切り替え（管理者の初めの並びは、オンの人のナビにだけ効かせるか、全員に効かせるかはレビューで決める）
- 今ある「試す人を選ぶ」形（overtime_day_check_rules：役職か人ごと）と同じ考え方にそろえる。
- 作る順の1（入社・退職の手続き：マネージャーが項目を編集・完了のベル・ナビに「📋 手続き」）は、この切り替えの対象にするかもレビューで決める。

## 2回目のレビュー（2026-10-17・プロの UI/UX デザイナーとシニアエンジニア・主な指摘はコードで裏取り）
### 作り方
- NavBar は15か所で同じ props を渡して描いている。NavBar の中で useAuth() を呼ぶ形にし、15か所は変えない（受け取りは残す）。🚨 ProtectedLayout に1つだけ置く形にはしない（ページを移るたびに数字を数え直す作りが壊れる）。
  ついでに直る：ShiftRequestPageWrapper の NavBar に userId が渡っていない（ベル・丸が出ない）。
- ボタンの表は lib/navItems.ts（key・名前・絵文字・色・path・出す条件・数字）。描く部品は1つ。
  今あるずれ：休暇のボタンは leaveBadge>0 で出すのに数字は leavePending（依頼だけのとき「0」）／端のはみ出しを計算し直す effect の deps が足りない→「出ているキーと数字を並べた文字列」1つに。
- 2段と1段は同じ箱の flexWrap を切り替える（2組作らない＝数字が2倍・Tab の移動が重なる）。
- 上の余白：今は各ページが 56〜110px を直書き（BoardPage・ShiftReportPage・App.tsx の各ページ・scrollMarginTop も多数）。
  書く場所を1つにまとめる（PreviewBodyOffset と取り合わない）。2段を使う人・スマホは常に2段目の高さぶん空けておき、縮んでも変えない（中身が動かない）。
  --topbar-height は ResizeObserver で実際の高さ。html の scroll-padding-top にも入れる（自動スクロール35か所でナビの下に隠れないように）。
- 縮める／開く：passive・rAF で間引き・値が変わったときだけ setState。しきい値を分ける（縮める＝scrollY>48 かつ下へ8px以上／開く＝上へ24px以上か scrollY<8）。
  iOS の引っぱり（0未満・最大より上）と resize（アドレスバー）は数えない。最初の状態は描く時点の scrollY から。150ms・prefers-reduced-motion なら動きなし。
  入力欄にフォーカスがある間・ベルの一覧・右上のメニューが開いている間は固定。1段に縮んだときとページを開いたときに、今いるページのボタンを見える位置へ（scrollIntoView）。今いるボタンに共通の印（白い下線など）。
- 🚨 連絡板（BoardPage）は 100dvh で中の箱だけが動く→ window のスクロールでは縮まない。連絡板と同じ作りの画面は初めから1段にするか、中の箱で縮めるかを決める。
- 入りきらないとき：入るかどうかは文字の大きさではなく実際に測る。2段目だけ横に流して赤い ›（3段にはしない）。2段目は全幅（ベルの下を空けない）。
- 設定の置き場所：app_settings に nav_order と nav_rollout（{two_row:{mode,user_ids,role_ids}, reorder:{…}}）。useFeaturePublished の読み込みを .in('key', …) の1本にまとめて入れる（通信は減る）。端末にも覚えておく（開くたびに1段と2段が切り替わって見えないように）。
  overtime_day_check_rules のやり方（表と関数）は使わない。管理画面の「役職ごと・個人ごと」の選び方（OvertimeAdminTab:868〜980）は部品に切り出して使い回す。
- 本人の並び：profiles.nav_order text[]（空＝管理者の並び）。loadProfileOnce の select で読む（通信は増えない）。authCache に任意の項目で足し、AUTH_CACHE_VERSION は上げない。
  🚨 列が無いと profile の読み込み全体が失敗する→必ず DB を先に出す。RPC set_my_nav_order（キーの形・数・重複を弾く・空は null・security definer・anon を revoke して実測）。
- 役職プレビュー中：本人の並びは使わず管理者の並び／試す範囲はプレビュー中の役職で判定／「設定」の並べ替えは保存できない。
- 管理者の並びは「並べ替えがオンの人」にだけ効かせる（オフ＝今のナビと同じ＝すぐ戻せる）。🏠 先頭・FAQ 最後は全員。
### 画面
- 管理画面の切り替え：3択の下に選んでいる人を名前の札で並べる。管理者自身が対象外なら「あなたは対象に入っていません（ご自身の画面は変わりません）」。オフに戻す前の確認文。
- 試している本人：「設定」の該当の欄にうすい灰色で「この表示は試行中です。お気づきの点は管理者までお知らせください。」（新しいプッシュは作らない）。
- 「設定」の並べ替え：🏠・⚙️・FAQ も「固定」の灰色の行で出す。押したらすぐ上のナビに反映・保存したら薄緑のカード。読み上げの名前。［最初の並びに戻す］は確認してから。長押しで並べ替える形は作らない。
### 出す順
- 2a：NavBar を表の形に（見た目は変えない・休暇の数字と deps のずれを直す・🏠 は全員）→ 2b：並べ替え（オフで出す）→ 2c：2段（オフで出す → 社長だけ → 実機 → 全員）。場所予約の担当に先に連絡。

## 2回目のレビューのあと決まったこと（2026-10-17・ユーザー確定）
- ⚙️（管理・管理者だけ）→ 🏠 の順（今のまま）。管理者以外は 🏠 が先頭。
- 連絡板のページは初めから1段（中の箱だけが動く作りのため・読む／打つ場所を広く）。ほかのページは2段→1段。
- 2段に入りきらないときは2段目だけ横に流す（隠れたボタンの数字は赤い ›）。3段にはしない。入るかどうかは実際の幅を測る。

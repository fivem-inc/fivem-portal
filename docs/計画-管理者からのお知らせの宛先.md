# 計画：管理者からのお知らせに宛先（2026-11-05・ユーザー確定の方針・設計レビュー前）

## きっかけ
- 管理者からのお知らせ（表 announcements）は宛先を持たず、どの経路も在籍者全員。正社員だけに知らせたいお知らせ（残業の表など）が出せない

## ユーザー確定（2026-11-05）
1. 宛先のボタンは連絡板と同じ：全員・正社員・パート・マネージャー・リーダー・こども・大人・管理部（いくつでも）＋個別に人を足す。「届く人◯人」と［届く人を見る ▼］
2. 宛先は作った時点の人で固定（あとから入社・役職が変わった人には出ない）＝通知を送った相手と画面に出る相手が必ず同じ
3. 出したあとも宛先を直せる：足した人にはその場でベル・メール・スマホ／外した人の画面（ホーム・過去のお知らせ・ベル）からは消す／外す人がいるとき保存の前に「外す◯人には、すでにメール・スマホの通知が届いています（取り消せません）」
4. 今までのお知らせは「全員」のまま変わらない

## 今の経路（調べた結果）と直す所
- 読む権限：announcements_select_all が using(true)（20260714120000）→ 宛先の判定に
- ホームの帯：App.tsx の AnnouncementBanner → lib/announcements.ts の fetchActiveAnnouncements（RLS で絞れば画面はそのまま）
- 過去のお知らせ：pages/AnnouncementsHistory.tsx（直接 select・休職中も開ける）
- ナビ🏠の数字・新着・［確認した］：my_home_feed（20261018232222・security definer＝RLS が効かない）
- 作成時の通知：Edge Function announcement-notify（87行で is_active の全員）
- リマインド：Edge Function announcement-remind（89行で全員分を1回だけ作りすべてのお知らせで使い回す）
- 休職中の扱い（staff_on_leave_ids でメールだけ外す）は残す

## 設計（案）
- 表 announcement_recipients（announcement_id, user_id, added_at, removed_at?）＝作った時点で宛先を人に展開して入れる（安否確認の safety_check_recipients と同じ方式）。GRANT は同じ migration に
- announcements に宛先の指定（recipient_presets text[]・recipient_extra_ids uuid[]）を控えとして持つ（画面の表示用・連絡板と同じ形）。🚨 判定には使わない（判定は announcement_recipients だけ）
- 宛先を人に展開する判定：連絡板の recipientPresetIds は画面（JS）にある → DB に同じ判定の関数を作る（announcement_resolve_recipients(presets, extra_ids)）か、画面で展開した id を渡して DB で在籍者か確かめるか（レビューで決める）
- 読める判定は1つの関数 announcement_visible_to(announcement_id, uid)：宛先の表に入っている（外されていない）か、宛先の行が1つも無い（＝今までのお知らせ＝全員）か。RLS と my_home_feed の両方がこれを呼ぶ
- 作る人・管理者（書き込み権限で全件読める）：帯には宛先どおり出す（画面側でも宛先で絞る）
- 送信：announcement-notify・announcement-remind は宛先の表を読む（rpc で DB の同じ関数）。宛先を足したときの通知は「足した人だけ」に announcement-notify を呼ぶ（引数に user_ids）
- 外したとき：その人のベルの行（source_type announcement の reference_id）を消す
- 退職者：今までどおり帯・my_home_feed で外れる

# 計画：残業の受理済み一覧に「表で見る」（給与計算用・2026-10-21）

## きっかけ
給与計算で、これまで人ごとのスプレッドシート（1人1枚・1日1行）を見ていた。
これからはアプリで同じ形を見たい。並びは給与で使っている**従業員番号の順**。

## 決まったこと（ユーザー確定・一問一答）
1. 従業員番号をスタッフに持たせる（profiles に列を足す）。最初の値は、いただいた一覧と名前で照らして一括で入れる
   （🚨 名前と番号の対応表は公開のリポジトリに書かない。本番の DB にだけ入れる）
2. 従業員番号の順を使うのは **2か所だけ**：
   - 残業の受理済み一覧：［表で見る］の表・並び順に「名前順（従業員番号）」を足す（今の 勤務日順・申請日順 は残す）
   - 管理画面の「勤務変更」のタブ：今の「名前順」を従業員番号の順に
   - 人を選ぶ・探す一覧（「全員 ▼」など）は今までどおり役職の順
3. 表の列：日付／曜日／通常シフト／労働時間（休憩）／理由／確認サイン（受理した人の名前・自己受理・確定（打刻ズレ））／変更（実務）シフト時間／時間数
4. 載せる申請：受理済みは普通に、確認待ちは灰色で「（確認待ち）」を添えて合計に入れない。差し戻し・取消は載せない
5. 1人ずつ表示。［◀ 前の人］［次の人 ▶］（従業員番号の順）と、名前・番号で探す欄
6. （既定として決めた）表に出す人＝残業を使う正社員。番号の無い人は最後／期間＝給与の期（16日〜翌15日・切り替えできる）／
   1日に申請が2件以上ある日は同じ日の行に並べる／合計時間は期ごとの残業の計算（lib/overtimeBalance の computeBalance）と同じ数字／
   番号は管理画面の「👤 ユーザー」で入れ・直せる／表を開ける人＝受理済み一覧を開ける人

## 作り（案・レビュー前）
- DB：profiles.employee_no（text・null 可・空でない値は一意）。読み書きの権限は profiles の今の決まりに乗せる（書けるのは管理者）
- 画面：components/admin/OvertimeAdminTab.tsx の［Excel出力］の横に［表で見る］→ 新しい部品（例 OvertimePayrollSheet）
  - 期の行は受理済み一覧と同じ読み方（overtime_reports・segments）。毎日の通常シフトは lib/overtimeShift の resolveNormalShift（残業の画面と同じ決まり）
  - 合計は computeBalance と同じ数え方
- 勤務変更のタブ（ShiftReportsTab）の applicantName の並べ替えを従業員番号の順に（番号が無い人は名前順で最後）

## レビュー（2体）で確かめたいこと
- 見せる日ごとの通常シフト（休み・会社休・振替など）を、どの関数で出すと残業の画面とずれないか
- 合計時間を computeBalance と一致させる方法（表の各行の時間数の足し算と、合計が食い違わないか）
- 従業員番号の列を profiles に足すときの権限（本人や他のスタッフから読めてよいか）

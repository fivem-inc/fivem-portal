・push・DB への反映・deploy は毎回許可をもらってから。push の許可は1回分だけ
・順番：① DB migration → ② Edge Function → ③ クライアントの push
・DB：begin/rollback でなりすまして実際に試す → 適用 → SELECT で実測。RPC は本番の実定義から起こす
・新しい関数は revoke … from anon を明示し has_function_privilege で確かめる。migration の番号は date +%Y%m%d%H%M%S
・直したあと：cd client && npx tsc -b && npx vite build ＋ npm run lint（rules-of-hooks 0件・件数が増えていないこと）。Edge Function は npx deno check
・push のあと git ls-remote で突合。本番の反映はチャンクのバイト数か文言で確かめる（短い間隔で curl しない）
・🚨 毎朝のお知らせの Edge Function は試しに呼ばない（その日のプッシュが上長にもう一度飛ぶ）
・UI の文言・配色・新機能は案を出して承認を得てから（一問一答・モック付き）。大きな設計は UI/UX とシニアエンジニアの2体でレビュー
・名前入りの作業ファイルは repo に置かない（D:\fivem-work\）。機能を変えたら社内FAQ と画面の注意事項も確認
・🚨 シェルの node -e に日本語とバッククォートを混ぜると崩れる。置き換えはスクリプトをファイルに書いてから node で実行する

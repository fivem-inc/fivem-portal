・DB：begin/rollback でなりすまして実際に試す → 適用 → SELECT で実測。RPC は本番の実定義から起こす（node で取り出して1か所だけ置換）

・push のあと git ls-remote で突合。本番の反映はチャンクのバイト数（1分おきに裏で確かめる・短い間隔で curl しない）
・Google カレンダーの出し直しは gcal-sync に { action: 'sync', source_type: 'overtime', source_id } を送る（冪等）。
  アプリ内ブラウザのログイン中の人の access_token で fetch すれば通る（パスワードはユーザーが入れる）
・UI の文言・配色・新機能は案を出して承認を得てから（文面は3案・実際のデータで見本）。説明は利用者から見て何が変わるかで
・機能を変えたら社内FAQ と画面の注意事項も確認。終わるとき引き継ぎを更新（古い ▶▶ はアーカイブの先頭へ）して commit・push

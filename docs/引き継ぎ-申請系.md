   受理 → 取消 → もう一度受理、休む日を減らす、欠勤を消す…のどれを何回やっても食い違わない。
   🚨 「◯◯が起きたら作る」と書くと、取り消しの経路が必ず抜ける
   （場所予約の㊸㊻㊽で3回踏んでいる形）。**状態を持つものはこの形で書くこと**。

   【動き】
     休暇が受理された        → 休む日ごとに場ができる（3日間なら3つ）
     受理を取り消した        → 場は**消さず** `cause_cancelled`（決めた割り当てが残っているかもしれない）
     もう一度受理した        → 元に戻る（割り当てがあれば decided・無ければ pending）。二重にならない
     休む日を減らした        → 減った日の場だけ閉じる
     欠勤の登録／取消        → 同じ扱い
     同じ日に休暇と欠勤      → 場は**1つ**（きっかけは休暇を優先。本番に2件ある）
     過ぎた日                → `closed_past` で作る。🚨 **古い列は触らない**
     有給奨励日の回答        → 場を作らない

   【🚨 逆向き（場 → 古い列）。これが無いとお知らせが止まらない】
   既存の cron `remind-leave-shift-adjust-daily` は `leave_requests.shift_adjust_status='pending'`
   を見ている。場の状態が変わったら古い列も書き換える。
   ・🚨 休暇1件に場は**日ごとに複数**。まとめ方は
     **1つでも未調整なら pending** → そうでなく decided があれば adjusted → 残りは no_change
   ・🚨 `closed_past` と `cause_cancelled` は**数に入れない**。入れると
     「未調整のまま過ぎた休暇」が勝手に調整済みになり、カレンダーの印が嘘をつく

   【🚨 印が巻き戻らないようにした（いちばん危なかった所）】
   場が**生まれるときの状態を古い列から引き継ぐ**（adjusted→decided／no_change→no_change）。
   いつも pending で作ると、**すでに「調整済み」にしてある7件**を何かの拍子に触っただけで
   場が pending で生まれ、逆向きの同期で古い列が未調整に戻り、カレンダーの印が巻き戻る。

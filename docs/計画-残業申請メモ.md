## 2. 決まったこと（画面）

### 2-1. 入口
- 申請画面の入力欄の先頭の行に、**左端［メモ（件数）］／右端［クリア］**（離して置く）
  - 🚨 **タブは増やさない**。**絵文字は付けない**（同じ画面の「📝 実績を報告する」と重なるため）
  - 押すと、同じ画面の中・ボタンのすぐ下にメモの枠が開く。もう一度押すと閉じる
  - **メモの枠を開いている間は、下の申請の入力欄を隠す**（閉じると戻る。入力した中身は消えない）
  - メモが0件のときは、押すとすぐ「新しいメモ」の入力が開く
- **締め切りが近いメモがあると、ボタンを黄色にして「メモ（3）締め切り近い」**（色＋文字の両方）
  - 黄色は既存の `#fff3cd` / `#ffeeba` / `#856404`（新しい色は足さない）。赤は使わない
  - 🚨 **ページの上には何も出さない**（「基本スクロールして見るので」ユーザー確定）
  - 「申請済み」のメモは数えない

### 2-2. 新しいメモを書く
| 欄 | 中身 |
|---|---|
| 何があった？（必須） | ［遅刻］［早出］［早退］［残業］［休日出勤］［調整休・振替・欠勤］［勤務地変更］［打刻忘れ］［打刻ズレ］［その他］ |
| 　└ その他の内容（必須） | 「その他」を選んだときだけ、その下に出る。別のボタンに変えたら書いた内容は消す |
| いつ？（必須） | ［昨日］［今日］［明日］［日付を選ぶ］。書ける日付は **90日前 〜 事前申請の上限（3か月先の給与期間まで＝`advanceMaxDate`）** |
| 時刻 | ［いま］［まだ分からない］［入力］。欄の名前は「何があった？」で変わる（下の表） |
| 勤務地 | 「勤務地変更」のときだけ出る |
| 理由（必須・打刻忘れ／打刻ズレは任意） | **書く欄1つ＋文例ボタン**。文例を押すと欄に文が入り、続けて書き足せる（申請画面の文例と同じ動き）。「〇〇校の応援のため」は欄の中で書き換える |
| 備考 | **なし** |
| ボタン | ［やめる］［メモを保存する］ |

- 「何があった？」は**思い出すための目印**。申請の種類を決めるものではない（申請画面は今までどおり時刻から種類を判断し、遅刻か調整遅出かは申請画面の2択で選ぶ）
- 選ぶボタンの色は 🎨🔒 択一トグル（未選択 `#e3f2fd`/枠`#90caf9`/文字`#1565c0`、選択中 `#1976d2`/枠`#1565c0`/白）
- 文例は申請画面の `reasonExamples`（OvertimePage.tsx 940行付近）と**同じものを lib の1か所から**使う

| 何があった？ | 時刻の欄 | 申請画面に入るところ |
|---|---|---|
| 遅刻・早出 | 出勤の時刻 | 最初の勤務時間帯の開始 |
| 早退・残業 | 退勤の時刻 | 最後の勤務時間帯の終了 |
| 休日出勤 | 出勤・退勤の2つ | 開始と終了 |
| 調整休・振替・欠勤 | なし | 終日の入力に切り替え（3つのどれかは申請画面で選ぶ） |
| 勤務地変更 | なし（勤務地を選ぶ） | 勤務地 |
| 打刻忘れ | 出勤の打刻・退勤の打刻（どちらも任意） | 「打刻ズレ」（`clock_only`）の入力に切り替え、理由「打刻を忘れた（あとで押した）」を選んだ状態。打刻の時刻も入れる |
| 打刻ズレ | 出勤の打刻・退勤の打刻（どちらも任意） | 「打刻ズレ」の入力に切り替え。理由は選ばない状態（メモの理由が打刻ズレの理由の選択肢と同じ文なら、それを選んだ状態） |
| その他 | 時刻（どちらでもよい） | 入力欄には入れず、理由の欄へ |

- 🚨 **「打刻ズレ」と「打刻忘れ」は別のもの**（2026-09-17 ユーザー確定「両方残す」）。
  残業ページの「打刻ズレ」＝仕事はシフトどおり終わったのに打刻が遅くなった記録（理由：打刻を忘れた／同僚と話していた／私用で残っていた／その他）。
  勤務変更報告（パート専用）の「打刻忘れ」＝`missed_clock`。**名前はどちらも変えない**
- 打刻忘れ・打刻ズレのメモは**今日以前の日付だけ**（打刻ズレは事後報告の新規でしか出せないため）。理由は任意
- 打刻ズレのメモの文例ボタンは、打刻ズレの理由の選択肢（`CLOCK_ONLY_REASONS` の「その他」以外）を使う

- 「いま」は**押した瞬間の時刻**を入れる（画面を開いた時刻ではない）
- 書いていない方の時刻は、通常シフトのまま

### 2-3. メモの一覧（枠の中）
- いちばん上に「※ メモは申請ではありません。」、その右に［＋ 新しいメモ］（薄い青 `#e3f2fd`/`#64b5f6`/`#1565c0`＝既存「残業なし」ボタンの色）
- 見出しは **今日／先の予定／過去**（灰色の文字。0件の見出しは出さない）。中は日付の古い順
- **1件1行**（スマホ幅360pxで収まる）
  ```
  9/17（木）遅刻 10:05 電車遅延のため…   ［申請］［修正］ ✕
  ```
  - 理由は灰色で同じ行、長いと「…」で切る
  - ［申請］［修正］は「クリア」と同じ灰色・高さ28px。**番号は振らない**
  - **削除は ✕**（枠なし・灰色・［修正］から6px離す・読み上げ名「削除」）
  - ✕ を押すと行のすぐ下に「このメモを削除しますか？［削除（赤）］［やめる］」（**赤が左＝既存の取消確認と同じ並び**）
- 締め切りの見せ方
  | メモの日付 | 黄色にするとき | 見せ方 |
  |---|---|---|
  | 今日・先の予定 | **今日と明日**（その日を過ぎると事前申請ができない） | **日付の文字を黄色にするだけ**（文字は付けない） |
  | 過去 | **給与の締め（支給月17日）の7日前から** | 行の頭に「**10/17まで**」の黄色の札 |
  | 過去で締めを過ぎた | — | 灰色の「締め切り済み」。🚨 経理の許可があれば出せるので［申請］は残す |
- **申請済み**：灰色の文字にし、［申請］の代わりに灰色の「申請済み」。✕ は残す
  - その日に申請がすでにある場合も「申請済み」（`uq_overtime_manual_per_day` で送信が必ず失敗するため）

### 2-4. メモから申請する
- ［申請］で申請画面に 日付・時刻・勤務地・理由 を入れる
  - 過去の日 → 事後報告／先の日 → 事前申請
  - **今日** → **メモの時刻を過ぎていれば事後報告、まだなら事前申請**。時刻が無い・まだ分からないときは事前申請
  - 開いたあと本人が［事前申請］［事後報告］で切り替えられる
- 🚨 **書きかけの入力や「申請の依頼」の対応中なら、その場で「いまの入力を消して、メモの内容を入れますか？」と聞く**（`startFromRequest` と同じ流儀）
- 申請画面の上に「**9/17（木）遅刻 のメモから入力しました**」の1行（ボタンなし）
  - ［メモから外す］は**置かない**
  - つながりが外れるとき：「クリア」を押した／別のメモの［申請］を押した（入れ替わる）／**日付を変えた**
  - 時刻や理由を変えただけなら、つながりは残る
- 送信に成功したら、**つながっているメモを自動で「申請済み」にする**（質問は出さない。成功カードはいつもの「申請しました」）

### 2-5. 保存・削除・失敗・上限
- 保存したら薄緑カード「**メモを保存しました**」／補足「**まだ申請はしていません。申請するときは、メモの［申請］を押してください**」（数秒で消える＋✕）
- 削除したら薄緑カード「メモを削除しました」
- **保存に失敗したら**：枠を閉じず入力を残し、薄赤で「保存できませんでした。電波のよい場所でもう一度［メモを保存する］を押してください」。
  あわせて**端末に1件だけ一時保存**し、次にメモを開いたとき「保存されていないメモが1件あります［保存する］［破棄］」。保存できたら端末から消す
- **20件まで**。🚨 **件数は画面に出さない**。20件のときに［＋ 新しいメモ］を押すと、書く画面を開かずに
  「メモは20件までです。使い終わったメモを ✕ で削除してから書いてください」（申請済みも数に入る）

## 3. 決まったこと（データ）

- **サーバー（DB）に保存**。スマホ・PCどちらからでも見られる
- **見えるのは本人だけ**（上長・管理者にも見せない）
- **メモの日付から90日で自動削除**（毎晩の cron）
- **1人20件まで**（画面だけでなく **DB でも止める**）

### 表の案（`overtime_memos`）
| 列 | 型 | 備考 |
|---|---|---|
| id | uuid | |
| user_id | uuid | 既定値 `auth.uid()`。profiles 削除で消える |
| kind | text | 10種の check 制約（late / early_start / early_leave / overtime / holiday_work / day_off / location_change / missed_clock / clock_only / other など・名前は実装時に決める） |
| kind_other | text | kind='other' のとき必須（check） |
| target_date | date | |
| time_start / time_end | time | 「まだ分からない」は null。保存は `toDbTime` を通す |
| location | text | 勤務地変更のとき |
| reason | text | 文例＋書き足しを**文字のまま1列**（文例の文言が変わっても古いメモが壊れない） |
| applied_at / applied_report_id | timestamptz / uuid | 申請済みの印 |
| created_at / updated_at | timestamptz | updated_at は既存の `set_updated_at()` トリガー |

### 権限・掃除
- RLS は `overtime_plan_items` と同じ形（本人のみ select/insert/update/delete・`to authenticated`・管理者も見ない）
- 🚨 `revoke all on overtime_memos from anon`／トリガー関数も `revoke execute … from anon`（**`from public` では外れない**）→ 適用後に実測
- 20件の上限：**insert 前のトリガー**で `pg_advisory_xact_lock(hashtext('overtime_memos:'||new.user_id::text))` をかけてから数え、21件目は独自のエラーコードで止める（前例 `20260915142603`）。画面はそのコードを「20件まで」の文に言い換える
- 掃除の cron：`target_date < 今日 - 90日` を削除。形は `20260909104709` と同じ（先に unschedule・他の掃除と時刻をずらす）
- 容量：46人×20件＝最大920行。問題にならない

## 4. 作り方（シニアエンジニアのレビューを反映）

### 🚨 落とし穴（必ず守る）
1. **メモの時刻が通常シフトで上書きされる**：日付を入れると通常シフトで時間を入れ直す処理がある（OvertimePage.tsx 797行付近・`filledForDateRef`）。
   → メモから入れるときは**下書きに時刻まで入れて保存し、フォームを作り直す**（下書きに時刻があれば上書きしない作り）。
   🚨 既存の `startFromRequest`／`startFromPlan` は**タブを切り替えることでフォームが作り直される**が、メモは同じタブの中から押すので作り直されない。親に `formKey` を持たせて増やす
2. **「どのメモから入れたか」は `FormDraft`（501行付近・この画面の中だけの型）に `memoId`／`memoLabel` を足し、自動保存（718行付近）にも必ず書く**。書かないと1文字打った瞬間に消える（`modifiedFromId` と同じ注意）
3. 送信成功は親の `onSaved` に渡す（`onSaved(gcalWarn, usedMemo)`）。下書きは送信直前に消えるので、先に控える
4. **打刻忘れ（`clockOnly`）は今の下書きに保存されていない**（664行付近）。流し込むなら `FormDraft` に足す
5. **勤務時間帯が2つある日の遅刻・早退**：最初／最後の時間帯を単純に置き換えると逆転する（下の「既存の不具合」）。
   lib に「時刻で時間帯を切る」関数を1本作り、メモと `buildTimeAdjustReport` の両方が使う
6. 締め切りの判定は **lib の1か所**（例 `lib/breakCalc.ts` の `isPayPeriodClosed` の隣に「まだ／近い／過ぎた」を返す関数）。日付は文字列で計算し `toISOString` を使わない。経理の許可（`grantedWorkDates`）がある日は申請を塞がない
7. 文例は lib に `reasonExamplesFor(種別, 終日の種類)` として出す。メモの種類→申請の種別の対応表も lib の1か所
8. insert/update/delete は **`error` と件数（`.select('id')`）を必ず見る**
9. 「今日」の区切りは、画面に戻ったときに取り直す（2963行付近と同じ）

## 6. 裏取りした事実（2026-09-17・コードを読んで確認）

- 送信成功で**履歴タブへ自動で移り、成功カードは4秒で消える**（OvertimePage.tsx 2581・3620行付近）→ 送信後に質問するのをやめ、自動で申請済みにした
- 下書きの自動保存は「申請の依頼」の ID（`applicationRequestId`）を持ち続け、送信でその依頼を「申請済み」にする（718・1454行付近）→ 依頼の対応中にメモを入れると別の日で依頼が完了扱いになり得る。置き換えの確認が必須
- 既存の取消確認は［取消を確定（赤）］が左、［やめる］が右（4029行付近）
- 残業ページの「打刻ズレ」は `clock_only`、勤務変更報告の「打刻忘れ」は `missed_clock`（別の種類）
- 今日の事後報告は、勤務の開始時刻前は送れない（1259行付近）／終了時刻前は確認が出る（1204行付近）
- 本人×日付で手動の申請は1件まで（`uq_overtime_manual_per_day`・取消は除く）
- 申請画面の文例ボタンは、押すと理由の欄に文を入れる（2320行付近）

## 7. 採らなかった案（理由つき）
- 文章だけのメモ／申請画面を丸ごと保存 … あとで使いにくい／その場で全部埋めるのは大変
- 端末だけに保存 … スマホで書いてPCで申請できない
- タブを増やす／ページの上に知らせを出す … ユーザー判断（タブを増やしたくない・スクロールして見る）

## 6. 無料プランでできないこと

### Supabase

| できないこと | 影響 |
|---|---|
| **プロジェクトは2つまで** | **満杯。練習用DBを作れない** |
| **自動バックアップが無い** | 自前のNAS夜間バックアップが唯一の命綱 |
| **巻き戻し（PITR）が無い** | 失敗しても戻せない |
| **データベースのブランチが無い** | 本番DBを分けられない |
| **ログは1日で消える** | 不具合の手がかりが翌日には消える |
| 容量：DB 500MB／ファイル 1GB | いまは余裕あり（DBは約27%） |

### Vercel

| できないこと | 影響 |
|---|---|
| **商用利用が規約上できない** | §8-① 要判断 |
| **ログが1時間で消える** | **不具合の証拠が最も早く消える** |
| 同時ビルドは1個 | 2人が同時に push すると順番待ち |
| 容量 | 転送0.3%・リクエスト3%。**問題なし** |

### GitHub

| できないこと | 影響 |
|---|---|
| **非公開**リポジトリでのブランチ保護・レビュー必須 | 他3件は非公開なので使えない |
| 鍵の自動検出（Secret scanning） | いまは自前の pre-commit フックで代替 |

🚩 **公開リポジトリなら「master へ直接 push させない」保護が無料で使えます。**
「push した瞬間に本番公開」というこのシステム最大のリスクに、費用ゼロで手を打てます。

## 8. 判断が要ること

### ① Vercel の商用利用 ⚠️ 最優先

公式に「Hobby チームは非商用の個人利用のみ」と明記され、商用利用の定義には
**コードを書く有給の従業員も含む**と書かれています。

🚨 **これは解釈であって確定ではありません。** 例として挙がっているのは決済・広告・
アフィリエイト・寄付の募集で、社内向け業務ツールは含まれていません。
公式も「迷ったらサポートへ問い合わせを」と案内しています。

**放置は勧めません。** 違反と判断されるとサイトが止まり、スタッフ約46名が使えなくなります。

→ まず **サポートに問い合わせる（$0）**。回答しだいで Pro（$20/月）を検討。

### ② 不具合の原因が追えない（費用ゼロ）

2026-09-05 に「休暇申請の完了バナーの ✕ を押すと画面が真っ黒」という報告がありましたが、
**ログが消えていて原因を特定できませんでした。**

さらに **このアプリには例外を受け止める仕組み（エラーバウンダリ）が1つもありません。**
そのため React が落ちると画面の中身が消え、地色 `#242424` だけが残って「真っ黒」に見えます。

→ **エラーバウンダリを入れれば、ログに頼らずその場で理由が読めます。**
　🚨 `App.tsx` を触るため、2人での事前調整が必要（未着手・未承認）。

### ③ GitHub の持ち主を揃えるか → **いまは不要**

他3件が個人アカウント `fivem-kyoto` にありますが、**会社が作り会社が管理しているなら
移す必要はありません**。移行の目的は「担当者個人と一緒に失われるのを防ぐ」ことなので、
会社のものであれば、その心配はすでにありません。

🚨 **むしろ触らないほうが安全です。** Vercel の公式には
「Hobby チームは Git 組織のリポジトリに接続できない」とあるのに、
`fivem-inc/fivem-portal` は現に無料でつながっています。**説明のつかない状態**なので、
一度切ると**同じようにつなぎ直せない恐れ**があります。

→ かわりに、**費用ゼロでこれをやると同じ安心が得られます**：
1. **どのアカウントのログイン情報が、どこに保管されているか**を書き残す
2. **2段階認証の復旧コードが「1人のスマホだけ」になっていないか**を確認し、
   紙に印刷して `docs/DISASTER-RECOVERY.md` の封筒と同じ場所へ
   🚨 **コードの中身はここにも Git にも書かない**

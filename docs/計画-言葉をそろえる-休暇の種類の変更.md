## 案
### 1. 言葉をそろえる（文言は3案とカラーのモックで決める）
- 役割ごとに言葉を1つに：
  - 受理の前に、その場で直す … ［直す］（案）
  - 取り消して、同じ内容で出し直す … ［取り消して出し直す］（案）
  - 取り消す … 入口［取り消す］→ 確認［取り消す］／［やめる］
  - 管理者へ頼む … 今の部品のまま（［📩 管理者に修正を依頼］［取消を依頼］）。文の中で呼ぶときも同じ名前
  - 確認の画面の戻る … ［戻る］（「修正する」は「直す」と取り違えるので使わない）
- 受理のあとに自分で直せない理由の1行を、残業・休暇・勤務変更で同じ形に（例：「受理済みのため、ご自分では直せません。直したいときは［📩 管理者に修正を依頼］から依頼してください。」）。理由が違うとき（締めのあと・振替休日の日が来た）は今の文を同じ形に寄せる
- 送るボタン・確認の画面に申請先の名前（例：［◯◯さんに送る］または確認の画面の「申請先：◯◯さん」を全部の申請で同じ場所に）。勤務変更の「確認依頼先」も「申請先」に
- 状態の名前は lib/applicationStatus の statusLabel に寄せる（各画面の表をやめる）
- 文と判定は lib に1か所（例：lib/applicationWording.ts）。画面はそこから引く
- 不具合 1〜5 は一緒に直す（6 は 2. で）
- 交通費・出張報告の「出したあとに直す道」は今回は作らない（言葉だけ）

### 2. 休暇の種類の変更を上長の判断に（まず「休暇 → 時間外調整休」）
- 上長（その休暇の受理者、または申請の依頼の権限がある人）が、受理済み（または受理の途中）の休暇から［種類の変更を依頼する］→ 新しい種類（時間外調整休・振替休日・欠勤）と理由 → 本人へ依頼
  - DB：application_requests に replaces_leave_id（置き換える休暇）。kind='overtime'・ot_content='chosei_off' など
- 本人：依頼のカード「◯◯さんから、10/31（有休）を時間外調整休に変える依頼が届いています」［時間外調整休で出し直す］→ 残業申請（終日）が入った状態で開く
- 送ったとき、置き換える休暇を同じ取引で取り消す：
  - 残業の行が入ったときのトリガーで、結び付いた依頼に replaces_leave_id があれば、その休暇を cancelled（理由「時間外調整休に変更（◯◯さんの依頼）」）。day_off_conflict はこの組だけ通す
  - 🚨 途中で失敗して休暇だけ消える・両方残る、を作らない（1つの取引）
  - 取り消した休暇の依頼を open に戻さない（reopen_application_request_on_cancel の手当て）
  - Google カレンダーの休暇の予定は消す（画面のあとで gcal-sync の delete・毎晩の片付けも拾う）
  - 休暇の受理者・経理に「取り消されました（時間外調整休に変更）」のお知らせ
- 受理：新しい残業申請はいつもどおり申請先の受理（自己受理の方はそのまま）
- 締め：残業の新しい申請は締め（17日）を過ぎると止まる → 依頼の画面でも「締めのあとは管理者へ」と出して依頼を作らせない
- 有休奨励日：時間外調整休が止まる日は、依頼の画面で止める（理由を出す）
- 逆向き（時間外調整休 → 有休）は次の段（残業の取消の決まりが違うため）
- 管理者の道（不具合 6・綴り 5）も一緒に直す

## レビュー（UI/UX・シニアエンジニアの2体・2026-10-26）で決め直したこと
### 言葉（1.）
- 入口のボタンは「したいこと」で1つ：［内容を直す］（その場で直す／取り消して作り直す の違いは、押したあとの確認の1行で伝える）
- 「取り消して出し直す」は、途中でやめると元の申請が無くなる（残業の cancelAndCopy は先に取り消す）→ 入力の画面に黄色い帯、またはやめたとき元に戻す
- 取り消す：入口［この申請を取り消す］（枠のボタン）→ 確認「元に戻せません」［取り消す］（赤）／［やめる］
- 確認の画面の戻る：［戻る］（休暇・交通費の［修正する］をやめる）。🐛 休暇の確認の画面の［修正する］に圏外で押せなくなる印（data-net）が付いている → 外す
- 受理のあとの1行は、依頼の状態（依頼中・対応済み）で文を切り替える（ボタンの名前が変わるため）。休暇には「種類（時間外調整休など）を変えたいときは上長にご相談ください」
- 申請先は、ボタンではなく確認の画面の送るボタンのすぐ上に「申請先：◯◯さん（役職）」を全部の申請で同じ形に（休暇は受理が何段もある・自己受理・名前が空のときに止められる）
- 状態の名前の表が7か所ある → lib/applicationStatus に（色は各画面か lib の「調子」）。依頼の種類の名前（App.tsx と lib/appRequests で違う）・申請先の名前の引き方（残業6か所・休暇3か所）・「管理者に依頼」の文（Edge も）を1か所に
- 不具合1〜6 は2体とも本当と確認（6 は上長の差し戻しの画面にもある・DB で「種類の無い調整休（区切りの日以降）」を止める）。追加：休暇の取消の失敗が console だけ／勤務変更の本人取消が受理済みも上書きしうる
### 休暇の種類の変更（2.）
- 🚨 休暇を取り消すのは「時間外調整休が受理された瞬間」（同じ取引）にする（案C）。送った時点で取り消すと、差し戻し・本人の取消で「休みが1つも無い日」ができる・シフト調整の相談が一度「取り消し」に倒れる。前例：振替休日の変更（furikae_change_apply）
  - 受理までは、その1組だけ休暇と時間外調整休が同じ日に並ぶことを認める（day_off_conflict の両方向・my_day_off_conflict・差し戻しからの再提出）。カード・受理の画面に「10/31（有休）からの変更」
- 1段目は「1日だけの休暇」に限る（複数の日の休暇は依頼の画面で止めて管理者へ）。【有給奨励日】の休暇も対象外
- 🚨 application_requests は受け取った本人が全部の列を書き換えられる（本番で確認：appreq_update に with check が無い）→ 置き換えの列と要の列は、あとから変えられないように見張る。依頼を作るときも確かめる（休暇の持ち主＝相手・依頼した人はその休暇の受理者かマネージャー以上か管理者・自分あては不可）。退職者・休職中の人は相手にしない
- 依頼と申請の結び付けは ID で（今の「同じ日の open を全部結ぶ」作りから外す）。取り消した休暇の元の依頼を open に戻さない・変更の記録に理由（印 app.change_reason）
- 上長の入口：申請の依頼のシート（残業・時間外調整休を選んだ日に休暇があれば黄色い枠で「この有休を時間外調整休に変える依頼にする」）＋勤怠カレンダーの休暇の予定から
- 本人のカード：見出し「休暇の種類の変更の依頼（◯◯さんから）」＋「10/31（金）有休 → 時間外調整休」＋「受理されると 10/31 の有休は取り消されます」［時間外調整休を申請する］／［有休のままにする］。残業と休暇の両方のページに出す。断る理由は専用（有休のままにしたい など）
- 締め：依頼の時点と送る時点の両方で見る。締めのあとの受理は管理者だけ（振替休日の変更と同じ）
- 本人から変えたいとき：休暇の修正依頼の画面に「時間外調整休・振替休日に変えたいときは上長にご相談ください」

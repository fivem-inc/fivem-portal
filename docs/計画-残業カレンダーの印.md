# 計画：残業申請のカレンダーに「出した日」の印／［シフト通り勤務した］の記録

状態：2026-10-12 に作って本番に出した（試し）。下の「8. 晃平さんの回答」が決定。4〜7 はレビューの経過として残す。

## 1. 困りごと（ユーザーの言葉から）
- 残業申請（事前・事後）はスマホで使う。日付はカレンダー（OvertimePage.tsx の SingleDatePicker）で選ぶ
- すでに申請を出した日が、カレンダーを見ても分からない
- 「出していない日に何もしていないか」を、毎月 履歴の一覧を見て確かめている人がいる
- 今のカレンダーでは、何もない日が「残業がなかった日」なのか「出し忘れた日」なのか見分けられない

## 2. 今の仕組み（コードで確認済み）
- カレンダー：SingleDatePicker（OvertimePage.tsx 286行〜）。7列・6週固定。
  - 選んだ日＝青の塗り（TOGGLE_BLUE）、今日＝青い枠
  - 会社の休館日は背景色＋日付の下に2文字（hooks/useCompanyCalendar.ts の CALENDAR_CELL_STYLE）
    休み＝灰 #e0e0e0／休館（社員出勤日）＝黄 #fff3cd／休館（有休奨励日）＝緑 #d4edda
  - 事前は今日以降、事後は今日以前しか選べない（min/max）
  - 同じ部品を「振替元の日付」選びにも使っている
- 本人の申請の読み込み：fetchOwn（OvertimePage.tsx 2528行）。applicant_id=本人・新しい順・**100件まで**
- appliedDates（2486行）：取消以外の申請がある日の集合。今は「残業のメモ」の［申請］を出さないのに使うだけ
  ⚠️ entry_type で絞っていない（休暇から自動で入る調整休 leave_auto なども入る）
- 一意制約 uq_overtime_manual_per_day：本人×日付で手動の申請は1件まで（取消は数えない）
  → 申請済みの日を選んでも入力は進み、**送った時点で DB に断られる**（画面で先に止めていない）
- 状態（lib/overtimeStatus.ts の STATUS_INFO）：requested（事前 確認待ち）／request_confirmed（事前 受理済み）／
  reported（実績 確認待ち）／confirmed（確認済み）／returned（差し戻し）／cancelled（取消済み）
- 「残業なし」系の既存の入口（4つ）
  ① 実績報告の［残業なし（通常どおりにする）］…事前申請した日だけ。差分0で自己確定（isPureZero）
  ② 事後報告の新規の［🕐 残業ではありません（打刻が遅れただけ）］…打刻ズレ（clock_only）。
     理由が必須（自分の都合だけを並べる＝サービス残業の同意記録にしない配慮）。差分0で確定・確認者なし。
     管理画面（OvertimeAdminTab → OvertimeClockInquiryPanel）の「打刻ズレの記録（残業なし）」に並び、経理が突き合わせる
  ③ 経理からの打刻の問い合わせへの回答「業務は終わっていました」
  ④ 表入力（OvertimeGrid）の実績報告の行の［残業なし］
- 通常シフト：lib/overtimeShift.ts の resolveNormalShift(patterns, 日付, 会社カレンダーの種類)。
  本人の勤務パターン（曜日ごと）＋会社カレンダーから決まる。シフトが休みの日は start_time が空

## 3. 決まったこと（ユーザー確定）
- カレンダーの印は **案C（文字で3種類）**
  - 「申請」…申請がある日（確認待ち・受理済み・確認済み）
  - 「通常」…残業なしで記録した日
  - 「戻し」…差し戻し（直す必要がある日）。赤字＋赤い枠
  - 何も出ていない日＝まだ何もしていない日
  - 休館日の2文字（休み／休館）と並ぶときは2段
- 事後で、任意で［シフト通り勤務した］を記録できるようにする
  - 押すと自分のその日のシフトが出る → ［この通り勤務した］ → もう一度確認 → ［記録する］（二重の確認）

## 4. 案（ここからがレビュー対象）
### 4-1. 印の出し方
- 対象：本人の申請（取消以外）。「申請」「戻し」は status から。
- 「通常」に数えるもの：①残業なしの実績報告（差分0・種別なし）／②打刻ズレ／新しい［シフト通り］の記録
- 印のある日を押したとき：入力欄に進ませず、カードを出す
  「10/9（木）はすでに申請があります（事前申請 受理済み）。同じ日に2件目は出せません。［この申請を見る］」
  「通常」の日：「10/8（木）はシフト通りと記録しています［記録を取り消す］」→ 取り消すと申請を入力できる
- 振替元の日付のカレンダーには印を出さない
- 100件の上限：カレンダーで見る月の分を、別に「日付と状態だけ」読む案もある（通信量に注意＝Supabase 無料枠）

### 4-2. ［シフト通り勤務した］の記録の持ち方
- 案X（推し）：新しい小さな表（例 overtime_day_checks：本人・日付・記録した日時・その時のシフトの写し）
  - 残業申請（overtime_reports）には入れない → 合計時間・受理の確認待ち・Googleカレンダー・上長への通知・
    一意制約（1日1件）に一切影響しない
  - 本人だけが書ける／消せる。シフトが休みの日・未来の日は記録できない
  - その日にあとから申請を出したら、申請を優先して表示（記録は残すか消すか → 要検討）
  - 掃除：1年より古いものを毎晩の cron で消す（記録を貯めるなら掃除も作る決まり）
  - 量の目安：社員 約40人 × 月20日 ≒ 月800行
- 案Y：②打刻ズレと同じく overtime_reports に差分0の確定済みで入れる
  - 経理の今の一覧にそのまま出るが、打刻ズレの一覧が毎日の分で埋もれる／1日1件の制約に当たる／
    あとで残業申請を出すときに先に取り消す手間

### 4-3. 経理に見せるか（ユーザーの問い：「経理は見られたほうがよくないか」）
- A：見せない（本人の確認のためだけ）
- B：経理（管理画面）で見られる。ただし打刻ズレの一覧とは混ぜず、別の見方にする
  例）人ごと・月ごとに「出勤の日のうち：申請／通常／何もしていない日 ◯日」。何もしていない日を押すと日付が出る
  → 経理が「出し忘れ」を本人に聞ける。打刻の突き合わせ（打刻ズレ）とは別の目的
- 気になる点：「何もしていない日」を経理が見られるなら、記録しないことが責められる空気になり、
  任意のはずの［シフト通り］が実質の義務になる。義務にするのか任意のままかは決める必要がある

### 4-4. 追加で決まったこと（2026-10-12 ユーザー）
- 休暇（有休など）の日にも印を出す（言葉は要検討。例「休暇」）
- 本人のシフトが休みの日も、まだの日と見分けられるようにする（ユーザーはする方向）
  ⚠️ カレンダーの「休み」は会社全体の休み（closed_all）に使用済み。本人のシフト休みは別の見せ方が要る
- 表入力（OvertimeGrid）には印・［シフト通り］を出さない。
  ※ 表入力の「通常シフト」の列は、シフトが休みの日にすでに「休み」と灰色で出している（OvertimeGrid.tsx 774行）

## 5. 守ること（このプロジェクトの決まり）
- master に push＝本番公開。DB → Edge Function → 画面の順。本番DBは1つ
- 新しい関数は anon から実行権限を外す（revoke … from anon を明示）。RLS の管理者判定は app_metadata
- `.update()/.delete()` は0件でもエラーにならない → `.select('id')` で件数を見る
- 新しい種類の通知は作らない（設定が無い＝全員に飛ぶ）
- 配色は既存の決まり（🎨🔒・lib/buttonStyles.ts：送る＝青・戻る＝枠）。絵文字は検証済みのものだけ
- 同じ判定・ラベルを2か所に書かない（印の判定は lib に1つ）
- Supabase 無料枠（通信量・DB 500MB）に注意

## 7. 修正案（ユーザーの判断待ちの所に ★）
- 印：申請／★報告（実績報告がまだ・橙）／★直す（差し戻し）／★なし（残業なし）＋休暇。強い順 直す＞報告＞申請＞なし
  札（自分の背景色つき）・10px 太字・全マス同じ高さ・凡例1行。文言は ★
- 振替元の日＝申請（カード「◯/◯の振替休日の振替元です」）
- leave_auto だけの日は止めない。appliedDates を manual・取消以外に直す
- カード（入力に進ませない）は状態ごとに次の一手：直す→［直して出し直す］／報告→［実績を報告する］／なし→［残業があったので申請する］
  確認済み・差分0の報告は「直したいときは管理者へ」
- 日付が下書き・メモ・依頼から入っても止まるよう、選んでいる日から毎回判定する。送信時の DB の断りの案内は残す
- 印は見ている月だけ細い列で読む（error を見る・読めなければ「印を読み込めませんでした」）。自動の定期読み込みはしない
- ［シフト通り］：★言葉／★確認の回数（ユーザーは二重確認を希望・UI は1回＋すぐ取り消せる）
  休暇・予定変更・開いている依頼がある日は記録させない。今日はシフトの終わりを過ぎてから
  ★あとで申請を出したとき 記録を自動で消す（UI）／残して申請を優先表示（エンジニア）
  ★保存期間 1年 or 3年（労基法109条・社労士に確認）
- 表入力：印は出さないが、classifyGridDay が［シフト通り］の日を知るようにして食い違いをなくす（第2段）
- 経理：★最初は見せない（両者一致）。使われ方を見てから第3段で判断
- ★シフト休みの日・休暇の日：文字を出す（ユーザー）／文字なし＋押すとカード＋「今月まだの日：◯日」の1行（UI）
- 段階：第1段（DB 変更なし・印とカード）→ 第2段（新しい表・［シフト通り］）→ 第3段（経理）

## 8. 晃平さんの回答（一問一答・2026-10-12）
- 休館・休み（会社カレンダー）は上の段、印は下の段
- 申請の印（案B）：事前（勤務日前の事前申請）→ 未報告（日が過ぎて実績報告がまだ・橙）→ 報告済（実績を報告）／事後報告の日＝事後
- 差し戻しの日＝差戻（履歴の「差し戻し」と同じ言葉・赤）
- 残業がなかった日（シフト通り・残業なしの報告・打刻ズレ）＝定時
- ［シフト通り勤務した］の確認は1回（シフトを見て［記録する］）＋記録後の緑の知らせに［取り消す］
- 定時と記録した日にあとで残業申請を出したら、定時の記録は自動で消す
- 経理・社長が給与計算の前に「残業があったか・なかったか」を見る。定時の記録は、管理画面の残業の一覧とExcel出力の両方に、申請と同じ表で混ぜて出す（別シートは手間）
  ＋打刻の確認の画面にも本人の記録を1行（案2）
  ⚠️ 行が月に約800増える → 一覧の絞り込み（状況）に「定時」を足して隠せるようにする（要確認）。差分0なので合計は変わらない
- Excel 出力は、出すときに「定時の記録を入れる／入れない」を選べる
- 定時の記録は任意（自分のメモ）。ただし打刻が遅れた日などは押すようにお願いする（経理からの確認を減らすため・お願いベース）
- 打刻が遅れた日：入口は1つ（何もない日を押す→［定時で記録する］［残業を申請する］）。定時の記録の画面に「打刻が遅れた日はこちら（理由を選ぶ）」→ 今の打刻ズレの入力を日付入りで開く。
  打刻ズレは今のまま（overtime_reports・残業申請の画面）。打刻ズレがある日は［シフト通り］を出さない。あとで打刻ズレ／残業申請を出したら定時の記録は自動で消す（DB のトリガー・新しい表の行だけ消す）
- 試す人：残業の管理画面に「役職ごと・個人ごと」の設定（overtime_calendar_choice_rules と同じ形・個人が優先）。
  最初は個人で三役のうち2人（社長・マネージャー1人・2026-10-12 ユーザー指示）。あとで役職「マネージャー」をオン。権限管理（共用ファイル）は触らない
- 🚨 管理画面の残業の一覧・Excel は全員の新しい順 300件まで（OvertimeAdminTab.tsx 302行）。定時を混ぜる前に給与期間で全件読む形に直す（今も欠けている可能性・件数を確かめる）
- 定時の記録は10年残す（10年を過ぎたものを月1回の cron で消す）。会社法の会計帳簿10年に合わせる
- 給与の締め（支給月17日）を過ぎた日は、定時の記録も取り消しもできない（DB の関数でも断る）。締め後に残業に気づいたら今と同じく経理の許可→申請→定時は自動で消える
- 休暇申請の日＝「休暇」の札／本人のシフトが休みの日＝背景なし・薄い字で「休み」
- 会社全体の休み（closed_all）のマスの2文字「休み」→「会社休」（CALENDAR_CELL_STYLE.closed_all.short・7画面で同時に変わる）
- 「今月まだの日」の1行は出さない

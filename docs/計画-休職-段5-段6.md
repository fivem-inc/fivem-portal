## 段5：休職のチェックリスト

### A. DB（migration 1本）

1. **表 `leave_checklist_items`**（項目）
   - 列：id・phase（'start'＝休職に入るとき／'return'＝復職するとき）・label・required・sort_order・active・choices（択一の選択肢）・
     auto_key（'push'＝スマホのお知らせの希望／'board'＝連絡板のお知らせの希望／null）・updated_by・updated_at
   - auto_key は1つずつ（unique where not null）。auto_key を足す・変えるのは管理者だけ（入社の auto_key と同じトリガーの形）
   - RLS：読む＝is_manager_plus()／追加・変更＝is_manager_plus()／削除＝is_admin()（入社・退職と同じ）
   - 初めの項目（**文言は承認をもらう**）
     - 入るとき：①「スマホのお知らせの希望を本人に確認する」［送る］［送らない］（auto_key push）／
       ②「連絡板のお知らせの希望を本人に確認する」［受け取る］［受け取らない］（auto_key board）／
       ③「休職中に使える機能（連絡板・交通費など）を本人に伝える」
     - 復職するとき：（案）「復職日を本人と確かめる」／「復職後の勤務（シフト）を本人と確かめる」

2. **表 `leave_checklist_checks`**（済み・対象外の記録）
   - 列：id・leave_id（staff_leaves・on delete cascade）・item_id（on delete set null）・item_label（写し）・choice・na・done_by・done_at
   - unique(leave_id, item_id)。phase は項目から決める（列に持たない＝2か所にしない）
   - RLS：読む・足す・消す＝is_manager_plus()
   - 🚨 auto_key の項目にはチェックの行を作らない（値と「確認した日時」は staff_leaves に持つ。行を作ると二重になる）→ トリガーで止める

3. **表 `leave_notes`**（メモ・チェックとは別の表＝退職・入社と同じ理由）
   - 列：id・leave_id・item_id・item_label・memo・updated_by・updated_at。RLS：is_manager_plus()

4. **staff_leaves に列**：push_asked_by・board_asked_by（だれが確認・変更したか。カードに「本人が設定で変更」などと出すため）

5. **関数 `staff_leave_set_pref(p_leave uuid, p_kind text, p_on boolean)`**（手続きのカードと本人の「設定」の両方が通る1本）
   - 呼べる人：マネージャー以上・管理者（終わっていない休職）／本人（自分の休職で、今日休職中のときだけ）
   - push_on／board_opt_in を変え、push_asked_at／board_asked_at・…_by を入れる
   - 🚨 本人が「設定」で変えたときも「確認した」扱いにする（本人が選んだ＝希望が分かった）
   - anon は revoke・authenticated だけ

6. **残りの数え方 `leave_checklist_remaining(p_leave, p_phase)`**（security definer・画面からは呼べない）
   - 使っている必須の項目のうち、ふつうの項目は「行が無い」もの、auto_key の項目は「確認した日時が空」のもの
   - 画面の数え方（lib）も同じ決まりで書く（lib/staffChecklist の1か所）

7. **「すべて完了しました」のベル**（入社・退職と同じ形）
   - 記録 `leave_checklist_done_log(leave_id, phase)`（1つの休職・1つの段で1回だけ）
   - 判定 `leave_checklist_done_check(leave_id, phase, actor)`：チェックの追加／項目の変更・削除／staff_leaves の …_asked_at の変更 の3か所から
   - 文：「✅ ◯◯さんの休職の手続き（休職に入るとき）がすべて完了しました」／「（復職するとき）」。ベルだけ（event_key を付けない）
   - 宛先：notification_settings 'leave:checklist_done'（site・マネージャー・社長・管理者）。済みにした本人と、休職中の本人には送らない
   - 🚨 中身をすべて exception で受ける（お知らせの失敗で操作を止めない）

8. **残りのお知らせ**（毎朝 9:00 の `staff_leave_daily_notices` を本番の実定義から直す）
   - 休職の初日・復職日の「◯日前（reminder_days_settings 'leave_checklist_notify'・初め 7・3・1）」と「当日」に、その段の必須が残っていればベル
   - 🚨 同じ日・同じ方に今ある知らせ（復職日の7日前・前日／初日の受理待ち）があれば**1通にまとめる**（2通にしない）
   - 宛先は今ある知らせと同じ（マネージャー以上と管理者・休職中の本人は除く）

9. **連絡板：受け取らない方を「まとめて選ぶ」から外す**（下の「決めてもらうこと」①）

10. **本人の「復職したあとのカード」のための値**：my_access_state の在籍者に `leave_returned`（復職日・休職の初日）を足す（終わってから7日のあいだだけ）
    - 🚨 mode は staff のまま（callerGate のため）。ホームを開くたびに問い合わせを増やさない（ログインのときに1回だけ読んでいる値に乗せる）

### B. 画面

1. **手続き（/retire）に「休職」のタブ**（入社・退職と同じ部品 RetireChecklistPanel を広げる）
   - lib/staffChecklist の CHECKLIST に 'leave' を足す。対象は「人」ではなく「休職の1回（staff_leaves の行）」なので、
     「対象の読み方」と「チェックの鍵（user_id／leave_id）」を CHECKLIST に持たせ、部品はそれを見る
   - カード：「◯◯さん　休職の初日 11/1・復職日 3/1（休職中）」。中に「休職に入るとき」「復職するとき」の2つの見出し
   - 出す方：予定・休職中の方は済んでいても出す。終わった休職は「復職するとき」に残りがあれば出す（済んだ方の表示で全部）
   - スマホ・連絡板の希望の項目：［対象外］なしの択一（［送る］［送らない］）。値と「確認したか」を分けて出す
     （例「送らない（初めのまま・まだ確認していません）」／「送る（本人が設定で変更・10/22）」）
   - その方が対応する予定の申請（受理待ち）：件数と一覧。管理者は［付け替える］（今の StaffLeaveModal を開く）
   - 管理者には［休職を修正］（同じ StaffLeaveModal）。マネージャーは見るだけ
   - メモの例：「例：書類は郵送で受け取る」（🚨 体調・病名などは書かないでください、を添える）
   - タブの人数は「必須が残っている休職」の数。ホームの黄色い案内（RetireChecklistBanner）にも休職を足す

2. **ベルの飛び先**（App.tsx の classifyNotif）
   - staff_leave:return_soon／pending／undecided・leave:remind・leave:checklist_done → /retire?kind=leave（&person=その方）

3. **「設定」ページ**（AccountSettings）：今日休職中のときだけ
   - プッシュ通知の行の中に「通知ON（すべて）／通知ON（安否確認・緊急のみ）」の選択（push_on）
   - 「連絡板のお知らせ」の行（全員あて・正社員あてなど）。届くもの・届かないものの説明。🚨 「休職」という言葉は使わない
   - 両方とも staff_leave_set_pref を通す（手続きのカードと同じ値）

4. **連絡板の作成画面**（BoardPage・お知らせの宛先）
   - マネージャー以上と管理者：受け取らない方は「正社員」などの欄から外し、いちばん下に「休職中（お知らせを受け取らない方）」の欄。
     一括のボタンには入らない。1人ずつチェックしたときだけ送る。一括を押したときに「休職中でお知らせを受け取らない方 1人は入っていません」
   - ほかのスタッフ：何も変えない（だれが休職中か分からないように）。→ 下の「決めてもらうこと」①

5. **復職したあとの本人のカード**（ホーム・7日間）
   - 薄緑「すべての機能をご利用いただけるようになりました。まだ確認していないお知らせが3件あります。［過去のお知らせ ›］」
   - 件数＝休職の間に届いた管理者からのお知らせで、まだ確認していないもの（0件ならその文は出さない）

## 段6：シフトの表から外す

### 調べてわかったこと
- シフト管理の5つの表（勤務表・こども／大人・管理部・掃除・勉強会）は「1週間の表」ではなく、**「曜日ごとの型が、基準の日から切り替わる版」**を基準の日1つで見ている
  （勤務表 applyFrom・こども／大人 baseDate・掃除 applyFrom・勉強会 baseDate・管理部 date）
- 5つとも ShiftManagementTab の中＝見られるのは管理者と、パソコンで開くマネージャー以上だけ → staff_leaves を RLS のまま読める（新しい関数は要らない）
- ShiftAdjustTab（シフト調整）と ShiftDirectoryPage（全員のシフト予定）は**リーダーも開ける**（権限 shift_adjust_view／shift_pattern_directory＝リーダー・マネージャー・社長・管理者）→ staff_leaves を読めない
- 🚨 名前の引き当て（nameOf・names）は全部の表で「全員の一覧」から作っている → **人の一覧そのものから消さない**。外すのは表に出す行・選ぶ欄・候補だけ
- 🚨 is_active=false で代用しない（こども表で「◯◯さんは退職しています」と出る）

### 決まり（案）
1. **判定**：基準の日から7日間（基準の日〜6日後）のうち1日でも休職中なら、その版の表には出さない（「休職の期間に入る週からは出さない」）。
   判定は lib/staffLeave に1か所（leaveActiveInWeek）。DB の staff_leave_active_on と同じ決め方
2. **シフト管理の5つの表**（マネージャー以上・管理者）
   - ShiftManagementTab が休職の行を1回だけ読み（終わった休職も、基準の日にかかるものは読む）、子の部品に渡す
   - 外す所：勤務表の表の行（visible）と PDF／こども・大人の人ごとの表・「休み」の行・選ぶ欄／管理部の人（締めの候補も）／掃除の人ごとの表・休みと担当なしの行・選ぶ欄／勉強会の選ぶ欄・プレビュー
   - 表の上に灰色の1行「休職中のため表に出していない方：◯◯さん（3/1 復職予定）」（マネージャー以上・管理者だけの画面なので出してよい）
   - 🚨 保存の中身（data.staff）は絞らない（全員を前提に保存しているため）。勤務表の登録は残す＝復職したら元の勤務がそのまま戻る
3. **シフト調整の「代わりの候補」**（リーダーも見る）
   - 新しい関数 `leave_ids_on(p_day date)`（security definer）：その日に休職中の人の id。呼べるのは shift_adjust_view か shift_pattern_directory の権限がある人・管理者だけ（ほかは空）
   - 候補（勤務予定がある人・休みの人）・出勤する人の選択欄・名前検索から外す。理由は出さない（静かに外れる）。名前の表示（nameOf）はそのまま
4. **全員のシフト予定（ShiftDirectoryPage・今日）**：同じ関数で今日休職中の人を外す（→ 決めてもらうこと④）

## レビューの結果（2026-10-21・UI/UX とシニアエンジニア・主な指摘は自分でコードを見て裏取り）

### 作り方を直すもの（自分で決めてよい作りの話）
- チェックリストは **LeaveChecklistPanel を別に作る**（入社・退職の部品は人＝profiles の行が前提・isHire の分かれ目が十数か所）。項目の編集・メモ・チェックの1行は共通の部品に抜いて両方で使う
- 残りの数え方は **RPC 1本**（is_manager_plus() で門・ホームの案内・タブの人数・パネルが使う）。lib に書き写さない
- 「復職するとき」の残りは**復職日の7日前から**数える（未定の間は数えない）。休職の間ずっとホームに黄色が出続けるのを防ぐ
- 復職の段の基準日＝早く戻った日（［今日から復職にする］）か復職日。🚨 0:00 の leave_sync が復職日に行を閉じるので、9:00 のお知らせは終わった行（直近・退職で閉じたものを除く）も見る
- 退職で閉じた休職・取消は、復職の段を一覧・案内・お知らせ・完了から外す
- 毎朝のお知らせは入社の hire_checklist_notify と同じ形（1人ずつ exception・送った記録）に作り直し、1人1日1通にまとめる
- 完了の判定はトリガーを staff_leaves に付けず、staff_leave_set_pref の最後で直接呼ぶ。項目の phase・auto_key はあとから変えさせない
- leave:* のベルは**関数の中でマネージャー以上と管理者に絞る**（通知設定で宛先を広げても「休職」の文字が一般に届かないように）
- 二択（スマホ・連絡板）は確認するまで両方とも塗らない（「今：送らない（初めのまま・まだ確認していません）」）
- 「設定」の行は通知に対応していない端末でも出す（いまのプッシュ通知の行は unsupported だと行ごと出ない）
- 復職のカードの値は my_access_state ではなく **my_home_feed** に足す（my_access_state は中で失敗すると全員が blocked＝ログアウト・Edge Function も 403）
- シフト：休職の行は取消以外を全部読み、子の表がそれぞれ自分の基準の日で判定（leaveActiveOnDay を7日ぶん）。灰色の1行は画面だけ（PDF・Excel に出さない）。
  マスに休職中の方が入っているときは黄色で知らせる。シフト調整の出勤のお願い・出勤の決定は DB でも休職中の人を断る

### 新しい表の GRANT（2026-10-21 元のセッションからの連絡・Supabase の変更 2026-10-30〜）
- leave_checklist_items／leave_checklist_checks／leave_notes／leave_checklist_done_log などの新しい表は、同じ migration に
  `grant <使う操作> on public.<表> to authenticated; grant all on public.<表> to service_role;`（anon には付けない）を書く。
  画面から読まない表（done_log・送った記録）は authenticated に付けない
- 適用後に `select has_table_privilege('authenticated','public.<表>','select');` で実測する

## 一問一答（2026-10-21 ユーザー確定）
- ① 連絡板：**休職中の方だけの「連絡板のお知らせを受け取るか」はやめる**（ユーザー確定）。
  - きっかけ：休職していることは、スタッフは皆シフトを見て知っている／何も届かないと浦島太郎になる／ベルは音が鳴らず未読を確かめられる
  - 連絡板のお知らせは今までどおり届く（受信トレイ・連絡板の数字・ベル）。送る人の画面は何も変えない（欄・注意の文なし）
  - 休職中の方に聞く希望は「スマホの通知」1つだけ（［すべて送る］［安否確認・緊急のみ］・初めは安否確認・緊急のみ＝push_on）
  - チェックリストの「連絡板のお知らせの希望」の項目・「設定」の連絡板の行・作成画面の「休職中（お知らせを受け取らない方）」の欄は作らない
  - 管理者からのお知らせ（announcement-notify／remind）：今は board_opt_in=false の休職中の人にベル・メールを送らない（段3の4）→ ベルは届くように直す。スマホは push_on のとおり（push-dispatch がもう止めている）
  - staff_leaves.board_opt_in・board_asked_at の列は残す（使わない）。消すのは別の機会
- ①の2 管理者からのお知らせのメール：**スマホの通知の希望に合わせる**（push_on=true の人だけ送る・初めは送らない）（ユーザー確定）
- ② シフト調整の代わりの候補・全員のシフト予定（リーダーも見る）：**黙って外す**（理由は出さない・名前で探しても「見つかりません。」）（ユーザー確定 案B）。
  関数 leave_ids_on は呼べる日付を絞る（今日の7日前〜60日先）・権限のある人だけ
- ③ シフト管理の表の週の判定：**基準の日から7日間ずっと休職中の週だけ出さない**。一部だけ休職の週は出して、名前の横に「11/1〜休職」「3/1 復職」の印（画面だけ・印刷・Excel には出さない）。
  出さない週は表の上に灰色の1行「表に出していない方（休職中）：◯◯さん 3/1 復職予定」（画面だけ）（ユーザー確定 案C）
- ④ 初めの項目（ユーザー確定）：休職に入るとき＝「スマホの通知の希望を本人に確認する」［すべて送る］［安否確認・緊急のみ］・「休職中に使える機能（連絡板・交通費など）を本人に伝える」／
  復職するとき＝「復職日を本人と確かめる」「復職後の勤務（曜日・校）を本人と確かめる」（案A）
- ④の2 復職するときに任意の「シフトの表に戻っているか確かめる」も足す（3件・ユーザー確定）
- ⑤ 復職した日から7日間のカード：**作らない**（ユーザー確定「ページが表示されれば分かる」）。
  休職中も管理者からのお知らせのベルは届く（①）ので、読み残しはベルと「過去のお知らせ」で分かる。my_home_feed も触らない
- ⑥ すべて済んだときのベル：「✅ ◯◯さんの休職の手続き（休職に入るとき）がすべて完了しました」（入社・退職と同じ形・ユーザー確定 1）。
  残り・復職日・初日のベルは提案のとおり（1人1日1通にまとめる）

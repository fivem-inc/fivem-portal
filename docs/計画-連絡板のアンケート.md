# 計画（案）：連絡板のアンケート（答えを集める・「お願い」から申請まで）（2026-10-29）

## きっかけ
- 行事の調整休・時間調整の希望確認を Google フォームで集めている（引き継ぎ (369)）。答えがアプリの外にあり、だれが答えていないか・答えを見て申請をお願いする流れが手作業。
- ユーザー確定（2026-10-29）＝案B（イ）：行事のためだけでなく、ほかのアンケートにも使える形で作る。

## ユーザーと一問一答で決めたこと（2026-10-29）
1. 答え方は4つとも：①1つ選ぶ ②いくつでも選ぶ ③文字で書く ④日付を選ぶ
2. 答えを見られる人：アンケートごとに選ぶ（「送った人＋写し(CC)の人」か「答えた人どうしも一覧を見られる」）
3. 答えの直し：期限までは本人が直せる（直したら一覧に「直した日時」）。期限を過ぎたら直せない
4. 使い回し：①送信トレイの前のアンケートを写して直す ②今のテンプレート（個人・全体）に質問ごと保存 の両方
5. 申請とのつなぎ（使うかはアンケートごとに選ぶ）：
   担当者が答えの一覧を見て、1人ずつ［この内容でお願いする］（答えが入った状態・直せる）→ ご本人に「お願い」が届く →
   ［了承する］／［相談したい］＋ひとこと → 了承したら同じ画面に［この内容で申請する］（日付・種類が入った申請の画面が開く）。
   相談したいなら担当者にベル → 担当者が直してもう一度お願いできる
6. 作れる人＝お知らせを送れる人と同じ（今の「お知らせ送信権限」）。「お願い」を使えるのは今の「申請の依頼」の権限（can_application_request）の人だけ
   （その権限が無い人が作ったアンケートでは「お願い」を選べない）

## 土台（今あるものを使う）
- お知らせの種別「✏️ 回答」（board_messages.deadline_type='answer'）に「質問票」を足す。宛先・写し・期限・送信予約・送信の取り消し・催促・未対応の数・控え（電波 段6）はそのまま使う。
  今の「✏️ 回答」（自由に1つ書く・Google フォームのリンク）は残す＝質問が0個なら今までどおり
- 答えたら今の board_confirmations にも1行（回答済み・未対応の数・「回答報告」がそのまま動く）。comment には答えの要約（読むだけ・正は答えの表）
- 「お願い」は今の申請の依頼（application_requests・ApplicationRequestSheet・ご本人の LeaveKindGuideCard／依頼のカード）に「了承」の段を足す
  （残業調整のご提案 OvertimeProposalResponse の「承諾」と同じ考え方。ただし提案の表は使わない＝申請の依頼のほうが申請画面へのつなぎ・期限・［対応しない］・催促まで揃っている）

## DB（案）
🚨 2026-10-30 以降に作る表は、同じ migration に GRANT（CLAUDE.md）。新しい関数は anon を明示して外す。
- board_survey_questions（新）：id, message_id → board_messages (on delete cascade), position int, kind text check in ('single','multi','text','date'),
  label text（200字）, help text（任意）, required bool, options jsonb（single/multi の選択肢の配列・各 {id, label}・30個まで）,
  date_from / date_to date（date のときの選べる範囲・任意）, allow_other bool（「その他（自由記述）」）
  ・作れるのは board_post の中だけ（本体と同じ取引）。送ったあとは変えられない（答えの意味が変わるため）。直したいときは取り消して出し直す
- board_survey_answers（新）：message_id, user_id, answers jsonb（{question_id: 値}・single＝選択肢 id・multi＝id の配列・text＝文字・date＝'YYYY-MM-DD' の配列）,
  answered_at, updated_at, edit_count。主キー (message_id, user_id)
  ・書くのは関数 board_survey_answer(p_message_id, p_answers) だけ（宛先にいる・期限内（JST の日付）・必須がそろう・選択肢が本物・日付が範囲内・文字の長さ）。
    同じ取引で board_confirmations も入れる／更新（comment＝要約）
  ・読む：本人の行／送った人・写しの人・管理者／results_public のときは宛先の人
- board_messages に列：survey_visibility text check in ('sender','respondents') default 'sender'／survey_onegai bool default false
  ・survey_onegai は送った人に can_application_request の権限があるときだけ true にできる（board_post で確かめる）
- board_notice_templates に survey jsonb（質問の並び・設定）。テンプレートから開くと質問も入る
- application_requests に列：survey_message_id uuid（どのアンケートから）・needs_accept bool・accepted_at・consult_note・consulted_at・round int（何回目のお願いか）
  ・status に 'awaiting_accept'（了承待ち）・'consult'（相談したい）を足す。了承 → 'open'（今の依頼と同じ＝［申請する］［対応しない］が出る）
  ・了承・相談は関数 app_request_accept / app_request_consult（本人だけ・awaiting_accept のときだけ）。担当者の出し直しは app_request_resend（consult → awaiting_accept・round+1）
  🚨 今の status を見ている所（依頼のカード・催促・ナビの数字・link_application_request_on_insert・reopen_application_request_on_cancel・enforce_appreq_*）を全部洗い出して、新しい2つの状態で壊れないか確かめる
- 掃除：答えはお知らせを消すと一緒に消える（cascade）。お知らせの完全削除の順番（BoardPage の削除の関数）に答えの表を足す

## 画面（案）
1. 作る（お知らせの作成・種別「✏️ 回答」のとき）
   - 「質問を作る」［＋ 質問を足す］→ 質問ごとに 答え方（1つ選ぶ／いくつでも選ぶ／文字で書く／日付を選ぶ）・質問の文・必須・選択肢（行を足す・並べ替え・消す）・日付の範囲
   - 「答えの見せ方」：［送った人と写しの人だけ］［答えた人どうしも見られる］
   - 「お願い（申請につなぐ）」：使う／使わない（権限が無ければ出さない）。使うときは「申請の種類」（残業申請の時間外調整休／遅出／早退／休暇申請）を決める
   - プレビュー（受け取る人の見え方）
2. 答える（受信トレイのお知らせを開く）
   - 質問が並ぶ。必須に印。［答えを送る］（青・1つ）。送ったら薄緑のカード「回答しました」。期限までは［答えを直す］
   - 「答えた人どうしも見られる」のときは［みんなの答えを見る］
3. 答えを見る（送信トレイのお知らせ・送った人と写しの人）
   - 上にまとめ（質問ごとの数・未回答 ◯人［催促］は今のもの）／下に1人1行（名前・答え・答えた日時・直した日時）
   - ［Excel で出す］（1人1行・質問ごとに列）
   - お願いを使うアンケートなら、各行に［この内容でお願いする］→ 窓（答えから入れた種類・日付・時間・ひとこと・期限・直せる）→［お願いを送る］。
     行に状態の札：お願い済み（了承待ち）／了承／相談あり（ひとこと）／申請済み／対応しない
4. お願いが届く（ご本人のホーム・ベル・残業／休暇のページの依頼のカード）
   - 「11/22 の行事の振り替えについて（◯◯さんから）／時間外調整休・12/3（水）でお願いします。」［了承する］［相談したい］
   - 了承 → 担当者にベル「了承されました」→ 同じカードに［この内容で申請する］（今の依頼と同じ・日付と種類が入った申請画面）
   - 相談したい → ひとこと（必須・200字）→ 担当者にベル「相談したいとの返事がありました：…」→ 担当者の一覧に「相談あり」→［内容を直してもう一度お願いする］
5. 写して作る／テンプレート
   - 送信トレイのアンケートに［この質問で新しく作る］（今の「引き継ぐ」に質問を足す・宛先は空・期限は空）
   - ［テンプレートに保存］に質問も入る（個人・全体は今の決まりのまま）
